# (not)AI Time Tracker

Локальный трекер времени для Android с независимым Kotlin-ядром. Он хранит одну активную сессию, её рабочие отрезки, классификацию и заметки. Историю можно исправлять, просматривать по дням и переносить через файлы. Сервер, аккаунт и сетевые API для работы не нужны.

Проект находится на этапе разработки. Android-приложение **0.9.1** — техническая оболочка для работы с ядром; удобный основной интерфейс ещё предстоит реализовать. Сборка и JVM/Room-сценарии имеют сохранённые результаты, но запуск на физическом Android-устройстве, поведение разрешений и доступность интерфейса пока не проверены. Подробности: [состояние проекта](docs/ACCEPTANCE_GAPS.md) и [проверки](docs/VERIFICATION.md).

## Возможности ядра

- Start, Pause, Resume, Stop и Switch на одной временной шкале; восстановление неопределённого хвоста после потери временной опоры.
- Личные карточки, избранные варианты, повтор, заметки и необязательная классификация через дерево типов и независимые признаки.
- Ручные интервалы, исправление истории с предварительным просмотром и одношаговая отмена в пределах процесса.
- Отчёты, календарная проекция истории, группы точных сохранённых вариантов и CSV. Зона отчёта задаётся явно; переходы летнего времени учитываются.
- Поиск и предложения из записанной истории с постраничным API; цели по времени или числу сессий; интервалы работы и перерыва Focus.
- Полная JSON-копия с предварительным просмотром, проверенной откатной копией и атомарным восстановлением. CSV-импорт добавляет историю после явного сопоставления колонок и классификации.

Эти возможности доступны через API ядра. Технический экран Android предоставляет базовые команды таймера, карточек, ручных интервалов, экспорта и восстановления, приём явно выделенного текста в редактируемую форму, а также настройки виджета, уведомления и overlay. Он не предоставляет полноценные экраны для всех API.

## Принципы

Учёт времени отделён от интерфейса. Все изменения проходят через `Tracker` и транзакцию `StateStore`; интерфейс не рассчитывает длительности и не записывает строки базы самостоятельно. Для обычного таймера не нужен постоянный сервис, секундные тики не пишут в базу.

Неизвестное время остаётся неопределённым до явного решения пользователя. Переименование или перемещение типа не переклассифицирует прошлые записи. Количества сохраняются точными десятичными значениями; величина всей сессии не распределяется по дням автоматически. Пересекающиеся классификации не добавляют время к общему итогу.

Системный Android backup и device transfer отключены в manifest/rules. Это настройка приложения, а не результат проверки всех OEM-механизмов. Ручной restore полностью заменяет данные; merge истории и синхронизация отсутствуют. Лимит JSON/CSV-импорта — 10 MiB.

## Сборка

Нужны JDK 17 или 21, Android SDK Platform 35 и Build Tools 35.0.0. Укажите `ANDROID_HOME` либо `sdk.dir` в локальном `local.properties`. Gradle Wrapper 8.13 включён; SHA‑256 дистрибутива закреплён. Kotlin 2.1.20, AGP 8.11.1 и Room 2.7.2 заданы в Gradle-файлах. Минимальная версия Android — 8.0 / API 26, target SDK — 35.

```sh
./gradlew :core:test :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Debug APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`. Для отдельной проверки на подключённом устройстве:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n dev.notai.tracker/dev.notai.tracker.android.MainActivity
```

Эти команды не означают, что проверка устройства уже выполнена. `--offline` допустим только при заранее заполненном кэше зависимостей. SDK, кэши, credentials и `local.properties` в Git не добавляются.
