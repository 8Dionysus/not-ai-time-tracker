# (not)AI Time Tracker

Локальный трекер времени для Android с независимым Kotlin-ядром. Он хранит одну активную сессию, её рабочие отрезки, классификацию и заметки. Историю можно исправлять, просматривать по дням и переносить через файлы. Сервер, аккаунт и сетевые API для работы не нужны.

Проект находится на этапе разработки. Android-приложение **0.12.0** имеет основной интерфейс на Jetpack Compose: немедленный старт, выбор занятия после старта, «начал раньше», иконки занятий, история по дням с исправлением, удалением, ручными записями и промежутками без записи, неизвестное время, Focus, план по дням, обзор с целями и отправкой итога, настройки с началом дня и напоминанием о долгой записи, светлая и тёмная темы; уведомление с быстрым выбором, виджет и плавающая кнопка. Прежняя техническая оболочка осталась отдельным экраном для функций без продуктового оформления. Сборка, JVM/Room-сценарии и Robolectric-отрисовка экранов имеют сохранённые результаты, но запуск на физическом Android-устройстве, поведение разрешений и доступность интерфейса пока не проверены. Подробности: [интерфейс](docs/UI.md), [состояние проекта](docs/ACCEPTANCE_GAPS.md) и [проверки](docs/VERIFICATION.md).

## Возможности ядра

- Start, Pause, Resume, Stop и Switch на одной временной шкале; восстановление неопределённого хвоста после потери временной опоры.
- Личные карточки, избранные варианты, повтор, заметки и необязательная классификация через дерево типов и независимые признаки.
- Ручные интервалы, исправление истории с предварительным просмотром и одношаговая отмена в пределах процесса.
- Отчёты, календарная проекция истории, группы точных сохранённых вариантов и CSV. Зона отчёта задаётся явно; переходы летнего времени учитываются.
- Поиск и предложения из записанной истории с постраничным API; цели по времени, числу сессий или различным дням с записанным временем; интервалы работы и перерыва Focus.
- Полная JSON-копия с предварительным просмотром, проверенной откатной копией и атомарным восстановлением. CSV-импорт добавляет историю после явного сопоставления колонок и классификации.

Эти возможности доступны через API ядра. Основной интерфейс покрывает таймер, выбор и поиск занятий, избранное и повтор, исправление, удаление и ручные записи, переключение задним числом, неизвестное время, Focus, обзор с целями, копию, восстановление и CSV-выгрузку, уведомление, виджет, плавающую кнопку и тему. Техническая оболочка (`TechnicalActivity`, «Настройки → Техническая оболочка») остаётся для CSV mapping, измерений, календарных вхождений и восстановления недоступной базы.

Новый backend-контракт сохраняет свои категории/подкатегории и именованные карточки отдельно от заметок. Карточки и категории теперь можно выборочно переносить без записанного времени, с зависимостями и проверкой конфликтов. Добавлены настройки границы дня/домашней зоны расписания и отдельный флаг тихой шторки: Room12, полный JSON15 (read1–15), selective4 (read1–4). Явное [дополнение начала текущей сессии](docs/START_BACKFILL_CONTRACT.md) сохраняет наблюдаемый таймер и отмечает подтверждённое время. Добавлены необязательное напоминание обычного таймера, ports окружения Focus и фактическая недельная проекция: [контракт](docs/ATTENTION_BACKEND_HANDOFF.md), [проверка C v3](docs/ATTENTION_VERIFICATION_2026_10_16.md). Подключение этих API к интерфейсу, настройкам цветов и тем пока не завершено. Фактическое покрытие и ограничения: [матрица](docs/CUSTOMIZATION_REQUIREMENTS_MATRIX.md), [контракт](docs/FUNCTIONAL_CUSTOMIZATION_HANDOFF.md).

Журнал попыток напоминаний теперь хранится в индексированном SQLite sidecar с сохранением всех identities/outcomes и миграцией прежнего JSON: [контракт](docs/INDEXED_SCHEDULE_RECEIPTS.md). Backend очистки связан с финальными seals архивов, legacy registration и writer/reference registry: [границы интеграции](docs/PRIVATE_COPY_BACKEND_BINDING.md). Один разрешённый AOSP software preflight дал частичный результат, без boot_completed и без приёмки устройства: [доказательства](docs/ANDROID_RUNTIME_PREFLIGHT.md).

## Принципы

Учёт времени отделён от интерфейса. Все изменения проходят через `Tracker` и транзакцию `StateStore`; интерфейс не рассчитывает длительности и не записывает строки базы самостоятельно. Для обычного таймера не нужен постоянный сервис, секундные тики не пишут в базу.

Неизвестное время остаётся неопределённым до явного решения пользователя. Переименование или перемещение типа не переклассифицирует прошлые записи. Количества сохраняются точными десятичными значениями; величина всей сессии не распределяется по дням автоматически. Пересекающиеся классификации не добавляют время к общему итогу.

Системный Android backup и device transfer отключены в manifest/rules. Это настройка приложения, а не результат проверки всех OEM-механизмов. Ручной restore полностью заменяет данные; синхронизации нет. Отдельный backend API выборочного переноса описан в [контракте нового прохода](docs/BACKEND_PASS_2026_10.md); его интерфейс ещё требует интеграции. Полные JSON-копии и восстановление читаются и пишутся потоково без общего лимита 10 MiB. CSV ограничен 10 MiB, 50 000 строк и 128 колонками. Полный граф данных всё ещё хранится в памяти; свободное место и память устройства ограничивают практический объём.

## Сборка

Нужны JDK 21 для тестов API36, Android SDK Platform 36 и Build Tools 35.0.0. Укажите `ANDROID_HOME` либо `sdk.dir` в локальном `local.properties`. Gradle Wrapper 8.13 включён; SHA‑256 дистрибутива закреплён. Kotlin 2.1.20, AGP 8.11.1 и Room 2.7.2 заданы в Gradle-файлах. Минимальная версия Android — 8.0 / API 26, target SDK — 36.

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease :app:lintRelease -PtrackerUnsigned=true
```

Собственная private-copy JNI использует закреплённый NDK r30 (`30.0.16248370`). Для host-файловых regression fixtures соберите отдельную библиотеку через `scripts/build-cleanup-host.sh JDK_DIRECTORY OUTPUT.so` и передайте `-PtrackerCleanupLibrary=/absolute/path/to/OUTPUT.so`; без этого параметра соответствующие JNI-тесты пропускаются. Host fixtures и компиляция четырёх ABI не являются Android device QA. Очистка имеет Context-bound backend session, descriptor/JNI-защиту и явные операции; UI-подключение и Android/device-приёмка остаются открыты. Границы — в [контракте очистки](docs/SEALED_ARCHIVE_CONTRACT.md).

С указанным флагом получаются неподписанные debug/release APK; ключи не создаются. Обычная debug-сборка без флага создаёт `app/build/outputs/apk/debug/app-debug.apk`. Для отдельной проверки такой подписанной debug-сборки на подключённом устройстве:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n dev.notai.tracker/dev.notai.tracker.android.MainActivity
```

Эти команды не означают, что проверка устройства уже выполнена. Для установки поверх ранее подписанного APK нужен тот же signing key; новая локальная debug-подпись отличается от APK исходной поставки. Исходный ключ не включён в репозиторий. `--offline` допустим только при заранее заполненном кэше зависимостей. SDK, кэши, credentials и `local.properties` в Git не добавляются.

Новая установка сразу получает полный готовый каталог: 1919 типов и 337 осей, версия 0.9.2.0, с короткими названиями обычным языком. APK содержит снимок словаря, manifest и проверяемые правила совместимости описательных обновлений. Исходные исследования и их обработчики отделены от приложения и сохранены во внешних архивах и истории Git. Обновление существующей установки требует preview и подтверждения; личные имена, архивность и прошлые классификации сохраняются.

Зона новой установки берётся с устройства один раз. Дальнейшие изменения зоны отчётов подтверждаются явно; зоны целей независимы. Технический экран (`TechnicalActivity`) предоставляет выбор карточки и избранного по ID, полный каталог с поиском и страницами, Focus с необязательным фоновым уведомлением, выбор календарного вхождения, явный CSV mapping, количества целого target, устойчивый SAF-экспорт и recovery без открытия неисправной базы.
