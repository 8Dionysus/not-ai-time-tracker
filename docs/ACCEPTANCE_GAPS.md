# Незакрытые пункты приёмки

Состояние после независимой сверки исходников с переданным документом. Три успешных JVM-сценария не означают полной приёмки Android-приложения.

## Незавершённый первый срез

1. **Собираемый Android/Room-проект пока не доказан.** APK, Room-generated implementation, exported Room schema JSON и Android lint не получены. Сборка дошла до отсутствующей принятой SDK-лицензии. В исходнике Room schema version=1, но сгенерированного файла схемы ещё нет.
2. **Room-проверки подготовлены, но не выполнены.** Не доказаны реальная SQLite-атомарность, уникальный слот активного сегмента, дисковый close/reopen и rollback адаптера. Успешны только те же три сценария на тестовом StateStore в памяти с сериализацией при повторном открытии.
3. **Нет проверки полного пути на устройстве/эмуляторе.** Не проверены Activity, SAF, уничтожение Android-процесса, sleep/reboot AndroidClock, доступность и фактическая работа политики backup. Нет screenshots/logcat сценария. QA-навык теперь доступен, adb-target — не подтверждён.
4. **Ответ правки уже, чем в документе.** Change содержит Snapshot, changedSessionIds и undoAvailable. Полные затронутые записи и пересчитанный Report не возвращаются одной операцией: UI вызывает data()/Reports отдельно. Между этими вызовами может пройти другая команда. Нужен согласованный read-model для результата правки. Изменение Measurement сейчас не добавляет его сессию в changedSessionIds.
5. **STALE не везде включает новый Snapshot.** Транзакционная проверка токена включает; ранний отказ Undo — нет. Безопасность отмены сохраняется, но контракт ошибки не полностью единообразен.
6. **Связь «Считать частью» минимальна.** partOf — явный строковый ключ области в карточке/историческом снимке. Нет реестра существующих типов, проверки ссылок на родительские карточки или наследования нескольких уровней. Сценарий «Шэдоуинг → language + es» поддержан; произвольная иерархия карточек — нет.
7. **Корректировки ограничены.** correctSegment правит один закрытый сегмент; switchedEarlier — только текущий непрерывный отрезок. Нет атомарной формы редактирования всей исторической сессии с несколькими сегментами/заметкой, исправления давно завершённого переключения или удаления ошибочного Measurement после исчезновения Undo.
8. **Модель количеств минимальна.** ID поля, версия смысла, единица, scope и целое неотрицательное значение есть. Отдельного каталога определений полей с человекочитаемым смыслом/типом, дробных значений и версии преобразований единиц нет. Это ограничение первого API, не обещание готового редактора измерений.
9. **Каталог минимален.** Пять шаблонов и данные вариантов есть; отдельных поисковых имён/алиасов нет. Техническая оболочка добавляет только первый шаблон кнопкой; полное управление каталогом доступно через API, не готовый UX.
10. **Нет атомарного результата «правка + выбранный отчёт», календарного сравнения произвольных DST-периодов.** Reports.compare требует равной физической длины окон. Календарные окна с разным количеством часов нужно поддержать отдельно, если они нужны UI. Текущий incomplete отмечает окно, доходящее в будущее, а не автоматически выравнивает его по прошедшей части предыдущего периода.

## Внешняя поставка

- Private GitHub repository не создан: callable create-repository отсутствует, существующая CLI-авторизация невалидна. Локальный Git и bundle существуют; remote не настроен.
- Доставка пользователю не подтверждается локальной ссылкой. Отдельно проверяется сохранение архива через поддерживаемую Library-загрузку; её фактический результат нужно смотреть в сообщении приёмки.
- Фактические модель/effort интерфейс не раскрыл. Из имени задания нельзя подтвердить модель; исполнитель не менял настройки и не создавал агентов.

## Отложено по согласованному объёму

Продуктовый UI и его объединение с ядром; виджет; overlay; уведомления и быстрые действия; Focus/перерывы/музыка/DND; календарь и копирование/старт события; выделенный текст; автодополнение, частые занятия и предложения событий; группировка похожих записей; цели/вехи/геймификация. Это бесплатные продуктовые требования будущих этапов, не реализованные функции первого APK.

Пользовательская граница дня, sync/merge, KMP, серверы и модельные API не реализованы; первые два требуют отдельного решения, остальные не нужны текущему локальному ядру. Полный журнал команд и постоянные commandId не вводились. Отмена одношаговая и не сохраняется между процессами. Весь граф Room переписывается по пользовательской команде; нагрузка на многолетней большой истории и размер/скорость не измерялись. JSON-импорт ограничен 10 MiB; управление накопленными rollback-копиями не реализовано.
