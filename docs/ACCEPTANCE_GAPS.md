# Состояние проекта и ограничения

Текущая версия Android-оболочки — 0.9.1. Схема Room — 3 с миграциями 1→2→3. Экспорт JSON использует формат 7, reader принимает форматы 1–7. Этот документ описывает текущую реализацию; исторические этапы перечислены в [истории](history/ACCEPTANCE_GAPS_through_v15.md).

## Реализовано в ядре

Один сохраняемый таймер, карточки и историческая классификация, повтор и избранное, ручная история, исправление закрытых интервалов и одношаговая Undo. Коррекция общей границы двух завершённых сессий имеет preview и атомарное сохранение.

Отчёты используют одну временную опору и явную зону. Календарь истории, группы точных сохранённых вариантов, черновики из текста/события и явные команды Start-now/manual-save доступны через [LocalEntries](LOCAL_ENTRIES.md). [Choices](CHOICES.md) предоставляет поиск и предложения из записанной истории. [Goals](GOALS.md) рассчитывает прогресс из истории; [Focus](FOCUS.md) использует ту же сессию и сохраняет рабочие интервалы без учёта перерывов как работы.

Room записывает изменённые строки, проверяет их чтением обратно и инвалидирует кэш по поколению базы. Горячие команды используют проверенное неизменяемое состояние. JSON restore — полная замена после preview и проверенного rollback. CSV-импорт — явное добавление с дедупликацией и происхождением источника.

Полная исследовательская проекция — 1918 типов и 337 осей; её установка явная. Bootstrap содержит пять технических типов. Исследовательские отношения и нерешённые семантические случаи не превращаются автоматически в новые правила времени или числа.

## Android-оболочка и проверка устройства

`MainActivity` остаётся техническим экраном: точное имя карточки, текстовые параметры и ISO‑8601 для ручных границ. Удобные экраны Choices, Goals, Focus и календаря отсутствуют. Это ограничение текущего приложения, при наличии API соответствующих функций ядра.

Виджет, уведомление, overlay и launcher actions имеют реализацию и JVM/Robolectric-проверки. Физическое устройство не проверено. Нужны проверки Activity/SAF, kill/restart, сон/reboot, системные разрешения, OEM-ограничения, launcher/виджет/overlay, TalkBack и увеличенный текст. Сборка APK и Robolectric не подтверждают эти сценарии.

Focus предоставляет countdown, DUE/RECOVERY и `signalKey`; Android runtime обрабатывает DUE callback с дедупликацией в процессе. Технический экран показывает состояние и безопасную подпись. Звук, гарантированная фоновая доставка и автоматический переход фаз отсутствуют. CalendarProvider имеет read-only адаптер выбранного occurrence с явным enable и проверкой READ_CALENDAR; экран выбора/opt-in и фактическое разрешение на устройстве отдельно. PROCESS_TEXT подключён к редактируемой форме, без auto Start/save. Музыка, DND и exact alarms требуют отдельного решения.

## Ограничения данных и эксплуатации

- Undo одношаговая и хранится в памяти процесса. Курсор Choices принадлежит одному `ChoiceView` и запросу.
- Группы `selectable=false` доступны для навигации, но не запускаются обычным Start. Автоматические предложения исключают архивные/невыбираемые варианты; явный исторический Repeat/Favorite имеет собственный контракт.
- Холодная загрузка и отчёты работают с полным графом. Списки истории копируются при изменениях. Скорость и расход батареи на многолетней истории телефона не измерены.
- Session/segment quantities относятся к целому target. Дневные представления нельзя суммировать как независимые величины. Нет моделей object/event IDs, snapshots/version, signed deltas и планов/расписаний.
- История не имеет merge или сетевой синхронизации. JSON/CSV ограничены 10 MiB. Автоматическая очистка rollback-копий отсутствует.
- RECENT_RECORDED и FREQUENT_RECORDED выводятся из редактируемой истории. Отдельный журнал успешных запусков, live item favorites, pins, ручной порядок и fuzzy/транслитерация не реализованы.
- Четыре остаточных ISCO-предложения — engraving/etching, ортопедическая обувь, фоточувствительные материалы и раздача образцов — требуют семантического решения отображения и остаются source-only без runtime ID. Tack-cleaning уже использует принятое reuse-отображение и не является пятым gap. Данные сохранены в источниках и outcomes.

Точные результаты ранее выполненных проверок и ограничения их доказательной силы — [VERIFICATION](VERIFICATION.md). Лицензия пока не выбрана.

## Границы передачи для интерфейса

| Область | Core | Android-адаптер | Интерфейс / устройство / отдельное решение |
|---|---|---|---|
| Таймер и история | Session/Segment, токены, correction/Undo, Reports и recovery | Общий Room runtime и readback | Технические команды есть; удобный интерфейс и device QA открыты |
| Choices | Полный paged API, причины совпадения и recorded suggestions | Доступен через runtime.tracker | Полноценная форма поиска и измерения на телефоне открыты |
| Goals | Прогресс из истории, периоды/зоны/фильтры | Использует тот же Tracker | Экран целей открыт; автоматические награды/уведомления не входят в контракт |
| Focus | Один таймер, work/break, pause/skip/recovery | Дедупликация DUE callback, видимый статус | Полные controls и device QA открыты; background sound/alarms отдельно |
| Calendar/grouping/drafts | Локальный календарь истории, точные группы, валидация EntryDraft | Выбранный CalendarProvider occurrence; all-day без рабочего интервала | UI выбора/opt-in/OS grant и device QA открыты |

| Полный каталог | Доверенные восемь источников, preview, атомарный package Apply | Восемь inputs в APK, runtime.prepareBundledCatalog(), catalogImports и приватный ResearchArchive | Форма preview/подтверждения открыта; установка остаётся явной |
| Файлы | JSON 1–7, CSV mapping/preview/apply, rollback | SAF JSON с строгим UTF‑8/BOM/лимитом | Удобная CSV-форма и device SAF QA открыты |
| Быстрые поверхности | Исходные токены и единый таймер | widget/notification/overlay/launcher | OS permissions/OEM/батарея/доступность не проверены физически |
| Исследовательские ограничения | Source-only residuals и точные quantity annotations | Новая модель не добавляется адаптерами | Object/event IDs, snapshots/version, signed deltas, plans/schedules отложены до выбора |

## Сквозная готовность бэкенда

Производственный runtime использует дисковый RoomStore. MemoryStore — второй исполнитель общего контракта в тестах; он не подменяет Android-хранилище.

| Путь | Реализация и сохраняемые данные | Проверяемый сквозной результат |
|---|---|---|
| Учёт времени | Tracker → StateStore; Session/Segment, classification, monotonic anchors | Start без карточки → поздняя разметка → pause/resume → switch → stop; закрытие/открытие Room сохраняет состояние; stale и recovery не меняют данные |
| Исправление и отчёты | correction preview → atomic mutation → Reports/CSV из того же Dataset | Коррекция границ → Undo → совпадающий итог, зоны/DST, без двойного времени по классификациям |
| Перенос | Backups/HistoryTransfer, PrivateRollbackStore, Room transaction | Экспорт → preview → чистое хранилище → Apply/readback; JSON 1–7 и CSV mapping; отмена/повреждение/stale и SQL failure не оставляют частичной истории |
| Поиск, цели и Focus | ChoiceView/Goals/Focus над сохраняемыми catalog/history/goals/focus | Полный обход каталога; поиск после редактирования; прогресс цели из истории; Focus pause/recovery/DUE без второго таймера или автоперехода |
| История и входы | LocalEntries, EntryDraft; CalendarOccurrences/PROCESS_TEXT | Календарь/DST/grouping → валидируемый черновик → явная запись; запрет календаря/отзыв/нет provider; входной текст лишь заполняет форму |
| Полный каталог | APK assets → trusted manifest → FullCatalogImports → ResearchArchive + Room | 1918 типов/337 осей; preview/cancel без записи; Apply сохраняет provenance и историю; повтор без дубликатов; конфликт/hash/missing/stale отклоняются |

Undo, preview, draft, search cursor, derived caches и DUE callback dedup живут в процессе намеренно. История, классификация, определения, настройки, цели и состояние Focus сохраняются в Room. Rollback и исходники исследовательского импорта сохраняются отдельно в app-private noBackup storage. Полный граф на холодной загрузке и память полного импорта остаются ограничениями архитектуры, а не проверкой скорости/ёмкости физического телефона.

Эта готовность позволяет строить полноценный UI на реализованных API. Технический экран всё ещё ограничен; продуктовая приёмка и физическое устройство остаются отдельными работами.
