# Текущее состояние и остаток · v18 / app 0.9.1

Это текущая точка входа для приёмки. Прежний текст сохранён целиком в [истории до v15](history/ACCEPTANCE_GAPS_through_v15.md). Его утверждения «Room пишет полный граф», «Focus/цели/поверхности не реализованы» и «входной каталог недоступен» описывают старые проходы, не нынешнюю сборку.

## Остаток сейчас

1. **Устройство и продуктовый UI.** APK не устанавливался и не запускался на устройстве в этих срезах. Нужны реальные проверки Activity/SAF, kill/restart, сон/reboot, widget/launcher/notification/overlay, разрешения/OEM, доступность и увеличенный текст. JVM/Robolectric их не заменяет. UI Диониса и Opus, включая формы Goals/Focus и удобный выбор, не разрабатывался. Технический экран всё ещё ждёт отчёт перед обновлением статуса и переписывает status.text на тиках; это не измеренная готовность пользовательского UI.
2. **Сигналы и интеграции.** Focus отдаёт countdown/DUE/recovery/signalKey; реальный звук и гарантированная системная доставка не реализованы. Локальный календарь истории, группировка точных вариантов и черновики/команды из события или текста реализованы (LOCAL_ENTRIES.md). Открыты Android Calendar Provider/выбор конкретного события, предложение ближайшего события из доступного провайдеру списка, PROCESS_TEXT/передача выделенного текста, музыка/DND и реальные системные разрешения. Эти адаптеры должны использовать существующие локальные API; отдельная модель истории не нужна. Ошибка/отказ будущей интеграции не должны блокировать локальный таймер.
3. **Дополнительная организация выбора.** Реальные launch-recents потребуют отдельной последовательности успешных запусков; текущие RECENT_RECORDED/FREQUENT_RECORDED честно выводятся из редактируемой истории. Отдельные live item favorites, detail pins, ручной порядок, каталог-only перенос с preview/merge, локализованные обновления seed с provenance, fuzzy/транслитерация и пользовательская проверка языкового поиска не добавлены. Группировка предложений по точному варианту не сливает историю.
4. **Каталог и массовые данные.** Полный принятый runtime-корпус — 1918 типов/337 осей; приложения/тесты подключают его существующим импортом. Технический bootstrap по-прежнему содержит 5 seed-типов, установка полного корпуса не стала скрытым действием при старте APK. Отдельные исследовательские residual/нечисловые количества не преобразованы в типы/числа по догадке: точные границы — [FULL_CATALOG_07.md](FULL_CATALOG_07.md), [QUANTITY_REVIEW.md](QUANTITY_REVIEW.md). Нужны измерения поиска/истории и ввода на телефоне, включая большие личные наборы; JVM-замер полного каталога не является device benchmark.
5. **Перенос и эксплуатация.** Автоматическая очистка rollback-копий отсутствует. Системный backup/device-transfer отключён manifest/rules; реальное поведение OEM не проверено. Полный JSON ограничен 10 MiB; merge истории и синхронизация не реализованы. Локальный Git и bundle есть; удалённый репозиторий, лицензия и публикация в этих проходах не создавались. Прежняя диагностика доступа находится в историческом файле.

## Реализовано и проверяется JVM-сценариями

- Один персистентный таймер, карточки, необязательные уточнения, повтор/избранное, ручная история, исправления и одношаговый Undo. Коррекция общей границы двух остановленных сессий имеет preview и атомарное сохранение.
- Историческая классификация, дерево и пересекающиеся признаки, версии измерений, точные Decimal, отчёты и CSV с общей семантикой времени. Полный каталог, исходные исследовательские файлы и архивы сохранены.
- Room schema 3: запись изменённых строк с проверкой обратно; immutable checked-state и компактный индекс обычного таймера, инвалидация между Room-подключениями. Полная валидация остаётся на недоверенных границах и общих правках. Нет ежесекундной записи/полного чтения для анимации. Списки истории на изменениях всё ещё копируются, холодная загрузка и отчёты читают граф целиком.
- Опциональные widget/notification/overlay и launcher shortcuts, единый runtime/token, разделение overlay-индикатора и обычного уведомления. Отмена Activity не отменяет уже переданную launcher-команду; непереданная сохраняется в Bundle. Реальное устройство остаётся открытым пунктом выше.
- Goals: длительность/число сессий, minimum/limit, периоды/зона/фильтр; прогресс из истории, включая явную неопределённость. [Контракт](GOALS.md).
- Focus: bounded work/break, pause/resume/skip/cancel, параметры следующих фаз, сохранение и явное recovery при потере process/clock evidence. Ни автоматических выдуманных циклов, ни второго таймера истории. [Контракт](FOCUS.md).
- Календарная проекция Reports с одной временной опорой, явной зоной и DST; группы точных сохранённых вариантов без слияния истории; эфемерные черновики из текста/события и явные Start-now/manual-save через текущие команды. [Контракт](LOCAL_ENTRIES.md).
- Общий paged read API выбора: типы/aliases/пути, карточки, snapshot-favorites, исторические варианты, причины совпадений и предложений, полный охват страницами. Индексы переиспользуются при тиках/буквах и неизменившихся данных. [Контракт](CHOICES.md).
- JSON format 7 с чтением 1–7: согласованный снимок, preview, проверенная откатная копия и атомарная полная замена. Повреждённый ввод не меняет старую базу; незавершённые хвосты/Focus не получают выдуманного окончания.

## Сохраняемые границы API

Undo одношаговая и в памяти процесса; курсор выбора принадлежит одному immutable ChoiceView и запросу. correctSession правит существующие сегменты; произвольный редактор состава формы не добавлен. Флаги архива/выбираемости локальны узлу, не наследуются детьми; группы доступны для навигации, но не предлагаются для запуска. Явный исторический Repeat/Favorite сохраняет прежний контракт, в том числе архивные случаи; автоматические предложения их исключают.

Срезы по пересекающимся признакам не складываются в общий итог. Session-scoped количества не распределяются по дням автоматически. Goals session count — уникальные участвовавшие сессии в окне, не сумма дневных счётчиков. Общий settings изменяет только Focus defaults; configureFocus — также план будущих фаз активного запуска. Подробности — соответствующие контракты, без скрытых догадок UI.

Обычные функции остаются бесплатным продуктовым объёмом. ИИ-подписка, сервер, обязательный аккаунт/синхронизация, KMP и игровая экономика не добавлялись. Фактические логи текущего среза: [evidence/draft-validation-v18](../evidence/draft-validation-v18/verification.json); прежние доказательства не заменены.


## Сверка доступного backend-остатка в v17

Просмотрены все пять групп выше: device/UI и реальные сигналы требуют отдельного этапа; чистая локальная часть календаря/текста/группировки выполнена. Дополнительные механики организации выбора (live favorites, pins, ручной порядок, launch ledger, каталог-only merge) не добавлены как обязательная предпосылка текущих бесплатных удобств: существующие snapshots/Choices уже обслуживают повтор и выбор. Исследовательские residual количества не интерпретируются без смыслового решения. Политика автоматической очистки rollback и расширение лимита JSON остаются эксплуатационными решениями; без них текущие проверенные копии работают. Это не объявление всего backend завершённым: новые найденные дефекты и согласованные сценарии продолжают обрабатываться, доступные локальные функции не помечаются заблокированными отсутствием провайдера.

Исправление приёмки v18: EntryDraft проверяется на обеих границах применения, независимо от фабрики/конструктора/copy. Редактируемая заметка допускает null как явное удаление; остальные ограничения и reference описаны в LOCAL_ENTRIES. Общий start/manual не изменён.
