## A — localization boundary

`CoreError.localized` exposes stable `ErrorCode`, typed `ErrorArgument` values, optional stable `ErrorReason`, `fieldPath`, and a stable resource key. Diagnostic exception messages remain for existing logs/compatibility; frontend must stop displaying or parsing them. Current core errors may have empty argument maps; consumers must handle that case.

`CatalogLabels` resolves sidecars keyed by catalog ID + stable ID + meaningVersion + BCP-47 locale. Personal override wins, then reviewed/offline content along explicit same-language fallback chains, then canonical original with `missing=true`. Draft quality and installed availability are independent. Catalog/history/IDs/JSON/CSV are never rewritten by display lookup. No reviewed multilingual packs are supplied: `catalog/locales/manifest.json` explicitly records missing/planned coverage, including Spanish and separate Hans/Hant. This manifest is not Android LocaleConfig or a claim of UI support.

`AppLocales` uses one `AppLocaleStore`; SYSTEM resolves current device languages on every read; EXPLICIT persists until an acknowledged change/reset. `AppLocalePreferences` is a separate durable Android SharedPreferences adapter with its own revision, no Dataset mutation. Both Android settings and in-app selection must submit the last confirmed change to this one preference. The adapter does not repeatedly push stale mirrors into Android settings. Frontend must bind LocaleManager/compatibility callbacks, migrate existing RU installations once, list only complete UI resources, and preserve drafts/navigation across recreation. That UI/platform integration and reviewed translations remain open.

## B — schedule API for Opus

Use `Tracker.scheduleCommand(ScheduleCommand)` and `Tracker.listOccurrences(first,last,deviceZone)` off the main thread. `Dataset.schedule` is authoritative; projections are computed and shared by all three surfaces. A series stores ordered rule revisions with effective dates, state, and a series revision. Weekly ISO weekdays and explicit extra dates form a union; dates/times are ISO civil values. Times are optional, not midnight UTC. Device-local preserves wall time; FIXED requires an IANA zone. reportZone is unrelated.

Actions: CREATE, UPDATE_FUTURE, SET_STATE (ACTIVE/DISABLED/ARCHIVED), OVERRIDE (SKIP/MOVE/REPLACE), START. Each command includes a fresh Tracker token, expected series/override revision, caller-retained idempotency key and exact payload. Same key + normalized payload returns the saved result before stale-token checks; another payload conflicts. Never create a new key to retry an ambiguous response. Results contain committed revision and affected IDs; fetch the current view separately after replay, since a receipt is the original result.

UPDATE_FUTURE requires an explicit effective date at/after the current device day and at/after the last rule effective date. Previous rules and exceptions remain, including superseded rules on the same effective date. Commands capture nested inputs before applying and normalize equivalent LocalTime spellings for receipt hashing. MOVE retains the original occurrence key; occupied dates in the same series reject unless `allowCollision=true`. Replacing an existing exception requires its revision. Started occurrences cannot be edited. A skipped/archived occurrence cannot start. START calls the existing checked timer transition and persists exactly one link and receipt in that transaction. Normal starts do not create links. A linked stopped session currently cannot be deleted; an explicit unlink/tombstone UX is a remaining integration choice, never a dangling link.

Gap resolution uses the first valid local time after the gap; overlap uses the earlier offset, both reported in projection diagnostics. Date-only plans have no instant. `alertsEnabled=false` by default; a reminder instant exists only with explicit reminder time, timed occurrence, and opt-in. At most one instant per occurrence is projected. Notification permission/delivery/DND and quiet shade rendering remain platform/frontend responsibilities. No automatic starts, facts, or completion marks are generated. Range is bounded to 3661 days.

## D — manual private-copy cleanup

`PrivateCopyCleanup` implements inventory→preview→separate confirmation, exact IDs/hashes, per-item warning acknowledgement, separate last-copy acknowledgement, command receipts, durable journal boundaries, quarantine progress, explicit resume and intact-group return. Reads/reconciliation never resume deletion. Partial unlink cannot be undone; only intact surviving groups can be returned. The storage interface requires same-gate maintenance, no-follow descriptor-relative operations, allowlisted manifest members, same-filesystem quarantine and file/directory fsync. No age purge exists.

**Production deletion is deliberately unavailable.** `PrivateCopyAudit` returns read-only Android candidates with hard blockers. Existing ViewModel writer/chooser coordination, forms and restore previews do not yet provide a common durable lease registry; archive hardlink graphs are not proven; Android descriptor-relative rename/unlink has not been implemented/validated. The audit is not an authoritative revisioned selectable inventory. Binding a path-based implementation would violate the cleanup contract. Thus no production `PrivateCopyStorage` is installed. Protocol tests use an isolated simulator, not real user files or proof of Android filesystem safety.

To enable D: implement and test the native/platform primitive; wire a durable ref registry and common maintenance gate into every export/chooser/form/restore/rescue path (coordinate with Opus for ViewModel/lifecycle changes); seal/verify full archive hardlink graphs; then provide authoritative monotonic inventory and journal adapter. Until then every candidate remains blocked. recovery-pending is never selectable; external SAF originals are never targets.

## E — selective transfer API

`SelectiveTransfer.export(selection)`, `inspect(package/text)`, `plan(package,groupIds,policies)`, `preview(plan)`, `apply(plan,operationId)`, and explicit `resume(operationId)` are separate from replacement JSON and CSV. Session groups contain every segment and only selected measurements; minimal type/card/axis/metric/unit dependencies accompany historical classification snapshots. Linked selected schedule/session components form one atomic group. Series include exceptions by default, with explicit exclusions. A one-sided start link blocks export unless that exact link is explicitly discarded; loss codes list excluded measurements/links/overrides and global settings/control assignments not portable, plus any goals/focus/favorites not selected.

Goals and favorites are separately selectable groups. Active Focus is an explicit dependency of its selected session; an exported live run becomes RECOVERY without device anchors. Packages carry version/min-reader/transfer ID/source Dataset, per-entity source IDs/revisions/hashes/origins and canonical group hashes. Inspect validates group graphs/hash. Plans are immutable copies tied to dataset token. Existing origin+hash and unchanged local group produce UNCHANGED; changed source/local data or identity collisions produce conflicts. BLOCK is default; explicit COPY remaps entity/reference IDs and retains origin. There is no name matching or silent replacement. Source clocks/revision numbers are not treated as cross-device ordering.

Operation preparation and every group result are durable Dataset transactions. A group either validates and commits whole, or records REJECTED with a reason. Independent groups continue; the operation exposes exact progress and partial status. Storage exceptions leave the current group pending. Resume skips committed groups and checks expected local revision/dataset/barrier before any new group; unrelated edits require a new plan. No startup auto-resume or blind rollback over later edits exists. `undo(operationId, expectedToken)` removes exactly the inserted objects/dependencies and restores previous provenance only at the operation’s unchanged final revision/barrier; later edits produce STALE. Full-replacement snapshots include pending operations and provenance.

Remaining E scope: editable dependency-resolution UI and durable SAF package staging/progress UI. Active control assignment receipts are intentionally nonportable; explicit loss codes disclose this. Current session/schedule/measurement/goal/favorite/Focus packages and conservative undo are functional. CSV retains its original append/dedupe/Undo semantics.
