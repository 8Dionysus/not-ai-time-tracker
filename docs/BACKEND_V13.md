# Android-адаптеры и проверенный путь таймера

Текущая Room schema — 4, JSON backup — 7 с чтением 1–7. Настройки поверхностей хранятся в metadata payload. Принципы хранения описаны в [BACKEND_V10](BACKEND_V10.md).

## Горячий путь и безопасность

`CheckedState` создаётся полным `validate` на холодном чтении, смене поколения Room и общих заменах/правках. Граф защищён копированием и `Collections.unmodifiable*`, включая вложенные коллекции. Переиспользование разрешено только для неизменившихся ссылок уже защищённого основания. Вводные builders, приведение `List` к `MutableList`, карты уточнений и списки справочника не могут испортить сохранённое доказательство проверки.

`Start/Pause/Resume/Stop/Switch` проверяют ожидаемый token, допустимый переход, временные основания, последние определённые границы, классификацию, диапазоны и суммарную длительность. Они конструируют закрытие/открытие сами; публичного параметра «данные доверенные» нет. `CheckedCommit.requireBase` запрещает применить результат от другого основания. Проверяется идентичность доказательства, а не только численная ревизия.

Room использует точные позиции изменённых сессий/сегментов и чтение записанных строк обратно. Закрытый сегмент сохраняется раньше нового открытого, уникальность открытого слота остаётся в SQL. Поколение инвалидирует кэш между отдельными `RoomDatabase`/SQLite-подключениями. При ошибке транзакции кэш сбрасывается. Обычная `StateStore.transaction` не обходит полную проверку. Для сторонних StateStore предусмотрен безопасный полный fallback.

`Tracker.snapshot`, `view`, `views` используют компактный индекс текущей сессии. Отчёты остаются явными операциями. Изменения прошлого, справочников, импорт и Undo всё ещё полностью проверяются. Списки сессий/сегментов при изменении копируются; UUID проверяется на уникальность. Это не заявление об O(1) всей команды или о готовности к миллионам записей.

## Коррекция общей границы

```kotlin
val preview = tracker.previewBoundary(token, leftSegmentId, rightSegmentId, boundaryEpochMs)
// Показать обе части; отмена формы ничего не меняет.
val change = tracker.correctBoundary(preview)
tracker.undo(change.state.token)
```

Только два определённых закрытых сегмента разных завершённых сессий с общей старой границей. Новая граница строго внутри объединённого интервала. Обе части сохраняются атомарно, сумма календарной длительности сохраняется. ID, классификация, заметки, import origin и количественные измерения не меняются. Измерения не делятся пропорционально времени. `changedSessionIds` содержит обе сессии; `Change.report/day` используют то же состояние. Повторный/устаревший preview отклоняется.

## Четыре Android-поверхности

Общая граница — TrackerRuntime на IO. Новые SurfaceAction содержат исходный TimerTarget(datasetId, sessionId, epoch, barrier) и token для совместимости. Несвязанная настройка не делает Stop устаревшим; переход таймера или restore меняет цель. Проверка исходной цели и разрешения выполняется внутри одной транзакции. Старые intents без TimerTarget сохраняют строгую token-проверку. Ошибка отображается и сохраняется в private feedback, без автоматической подстановки нового token. Immutable PendingIntent identity содержит исходную цель.

Настройки: `Settings(reportZone, surfaces = SurfaceSettings(widget, notification, overlay))`; все три значения по умолчанию false, сохраняются в Room и полном JSON. UI меняет отдельный флаг через `tracker.settings(token, oldSettings.copy(...))`, сохраняя прочие настройки. Разрешение ОС и пользовательское предпочтение — разные состояния. Импорт true не предоставляет разрешений ОС и сам не запускает overlay из фона.

| Поверхность | Реализация и выключение |
|---|---|
| AppWidget | RemoteViews: безопасный статус, Start/Pause/Resume, Stop, открытие приложения для Recovery. `updatePeriodMillis=0`; обновление на коммитах/событии host. При false команды исчезают, остаётся неработающая подсказка открытия настроек. Место виджета принадлежит launcher: приложение не удаляет его с рабочего стола, пользователь удаляет сам. Отключённый виджет не обновляется на каждом коммите. |
| Уведомление | Обычное уведомление с действиями, без FGS. Отдельный канал `timer_controls`; opt-in и POST_NOTIFICATIONS на API 33+. При false/отказе отменяется. Без названий занятий/заметок, PRIVATE visibility. |
| Overlay | Только `FloatingTimerService`, specialUse FGS, SYSTEM_ALERT_WINDOW. Запуск только из resumed Activity после opt-in и проверки разрешения. Не используется исключение фонового старта. `START_NOT_STICKY`, без BOOT receiver; после смерти процесса возвращается при следующем видимом открытии приложения, если разрешён. AppOps watcher отслеживает отзыв доступа. False останавливает сервис и снимает окно. |
| Launcher | Статический ярлык открытия приложения плюс динамическое действие Start/Pause/Resume с token. Динамическое действие открывает Activity, потребляется один раз и передаёт исходный token ядру; поворот не повторяет его. Устаревший закреплённый ярлык не получает автоматически новый token. При Recovery динамический ярлык disable/removeDynamic; pinned нельзя удалить программно. ОС может ограничить обновления: старое действие безопасно откажет, статическое открытие остаётся доступным. |

Плавающее окно имеет отдельный обязательный notification ID/channel `floating_controls`. Выключение обычного управляющего уведомления не скрывает индикатор сервиса. При отказе POST_NOTIFICATIONS Android всё равно показывает FGS в Task Manager, хотя шторка может его не показывать. Отказ/ошибка разрешения оставляет доступным обычный таймер. Нет dataSync FGS, точных alarms, wakelock, ежесекундных записей или циклов фонового отсчёта.

Технический экран предоставляет переключатели и состояние разрешений. Основной статус обновляется после расчёта отчёта, затем перерисовывается на тиках. Поверхности показывают состояние и кнопки; удобный основной интерфейс и отдельная анимация счётчика ещё не проверены.

Официальные основания: [типы FGS и specialUse](https://developer.android.com/develop/background-work/services/fgs/service-types), [ограничения фонового старта](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [AppWidget](https://developer.android.com/develop/ui/views/appwidgets), [создание shortcuts](https://developer.android.com/develop/ui/compose/system/shortcuts/creating-shortcuts), [управление pinned shortcuts](https://developer.android.com/develop/ui/compose/system/shortcuts/managing-shortcuts). Проверка соответствия specialUse требованиям магазина приложений не проводилась. Публикация исходного кода не означает одобрения магазином.

## Файловые и внешние входы

Полный SAF restore читает private staged file через потоковый Backups.prepare. Полный export сохраняет private operation/file и передаёт chooser только ID. Convenience byte API остаётся bounded для старых маленьких callers. [PORTABILITY](PORTABILITY.md) описывает большие копии и recovery.

runtime.catalogImports устанавливает проверенный [готовый словарь](RUNTIME_CATALOG.md) через preview и Apply; новая база получает его сразу. Сырые исходники и preparation readers не входят в APK.

`runtime.calendarOccurrences.readSelected(reference, enabled=true)` читает только конкретное вхождение события: eventId, begin и end задаются явно и проверяются в query и результате. По умолчанию функция выключена. После явного включения требуется фактически выданный READ_CALENDAR; адаптер не вызывает prompt и не выдаёт себе доступ. Denial/revocation, отсутствующий provider и неверное вхождение возвращают отдельный результат. `occurrence.draft()` предлагает title и интервал, для all-day — interval=null. Preview не пишет историю; запись проходит только через явные команды EntryDraft.

`ProcessTextDrafts.read(intent)` принимает только ACTION_PROCESS_TEXT/text/plain и EXTRA_PROCESS_TEXT. Полная строка сохраняется в редактируемой заметке; неизвестное/пустое/слишком длинное содержимое отклоняется. Технический экран спрашивает перед заменой уже заполненной заметки. Никакого чтения clipboard, автоматического Start/Save или сети нет. OS chooser и поведение конкретных приложений остаются непроверенными на устройстве.

`runtime.focusDueSignals.consume(snapshot.focus, callback)` обрабатывает DUE по signalKey в рамках runtime. Повторный сигнал и возврат к нему через одношаговую Undo не вызывают callback снова; ошибка callback остаётся retryable. Технический экран показывает безопасную подпись. Consumer не пишет историю и не переключает фазу. Дедупликация хранится в памяти процесса; это не гарантированная фоновая доставка, звук или alarm. [Focus](FOCUS.md).

## Lifecycle launcher-команды

`ShortcutCommands.submit` сразу передаёт команду в scope общего runtime. Activity ожидает Deferred; отмена ожидания не отменяет уже переданное действие. Непереданное действие сохраняется в instance-state Bundle. После передачи pending очищается, старый launch intent не повторяется с новым token. Гибель всего процесса до транзакции может оставить действие невыполненным; автоматического replay нет.

## Проверки и пределы

Три общих интеграционных сценария исполняются на Memory и Room/Robolectric API 35. Android-часть проверяет token/URI, stale и двойное нажатие, disabled/permission denied, RemoteViews, безопасный текст уведомления, launcher и отмену ожидания Activity, а также файловый ввод, CalendarProvider через контролируемый cursor, PROCESS_TEXT и Focus cue consumer. Точные результаты текущего кода — [VERIFICATION](VERIFICATION.md).

Сохранённый JVM-замер [backend-v13](../evidence/backend-v13/verification.json) использовал 2000 закрытых сегментов, 1923 типа (1918 импортированных и пять seed), 337 осей, два прогрева и семь измерений. Он сравнивал оптимизированный путь с безопасным StateStore fallback поверх того же Room, а не с прошлым commit. Замер не доказывает скорость телефона или плавность интерфейса.

Установка/запуск на физическом устройстве не проверены. Реальные launcher/виджет, OS prompts, overlay-окно, FGS/OEM, отзыв разрешений, CalendarProvider и доставка внешнего текста требуют device QA.

Новая база получает готовый каталог и локальную зону устройства; существующая установка сохраняется до явного обновления. CalendarOccurrences предоставляет list/nearest с ограниченным диапазоном и cursor; UI запрашивает READ_CALENDAR только при пользовательском выборе, показывает страницы и повторно проверяет выбранное вхождение.
