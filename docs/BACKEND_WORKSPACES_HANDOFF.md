# Backend workspaces and lifecycle handoff

Current accepted boundary: backend runtime/controllers, Application/manifest wiring and file adapters. Compose, MainActivity, TechnicalActivity, UI ViewModel, resources and surface rendering are unchanged by this pass. The separate caller patch is explicitly unaccepted and must be reviewed by Opus. No new timer, importer or Dataset store exists.

## Saved schedule commands

`TrackerRuntime.schedule.prepare(command)` canonicalizes and stores the caller's exact idempotency key, payload hash, expected Dataset/revision and command in the existing FormFiles directory. It returns `(id, revision)`. `execute(id, revision)` checks the draft and uses the existing Tracker receipt; retry after a lost response/save uses the SAME key. A saved result is returned even when the old revision is supplied on replay. Another payload under the same key refuses. No command is auto-executed on launch. `read`, `inventory`, `pending` and explicit `abandon` support resumed review. Inventory exposes unreadable form IDs separately; an unrelated malformed form is preserved. Showing or saving a plan creates no session.

`schedule.state`/`current()`/`refresh()` expose one immutable `ScheduleViewState` from ONE captured revision/moment: token, barrier, asOf, day policy, surfaces, device zone, occurrence projections and next civil boundary. Home/widget/quiet shade consume this same projection. Date-only remains date-only. `settings.schedule` is independent of reportZone. The next boundary uses the same gap/fold/day resolver; it is never now+24h.

## Quiet projection and platform changes

Install application-scoped `ScheduleProjectionConsumer` objects through `ScheduleProjectionBinding.install`. IDs are stable and unique. They invalidate/render data only. A quiet shade consumer supplies an already existing silent MIN/LOW importance channel and reports actual connection through `available`. Widget requires an actual host widget ID and the enabled setting. No renderer or default visible notification is supplied here: Opus owns it. With no connected enabled background consumer there is no projection alarm and its static receiver is disabled. HOME alone does not keep a wake-up.

For an active background consumer the operational journal records one inexact RTC wake-up at the next civil boundary, separately from reminders/alert receipts. Repeated/early/obsolete hashes are inert; time/zone/date changes recompute actual day and never replay missed days or create facts. Failure disarms the projection wake-up without replacing an unreadable journal. Runtime observes committed views, foreground Activity callbacks, configuration and protected platform time/channel/block broadcasts. Each refresh runs independently so Focus failure cannot suppress schedule refresh. Recovery unregisters the old runtime receiver. Renderer installation after cold startup is explicit; a cold receiver with no installed consumer disarms. OEM delivery punctuality and permission callbacks with no OS lifecycle/broadcast remain device/UI integration acceptance.

No polling loop, FGS, permission prompt, sound, exact-alarm permission or timer auto-start is added. Existing interrupting `AndroidScheduleDelivery` factory/receipt contract remains separate. `ScheduleNoticeBinding.install` must use the frontend's localised factory; projection never turns on alerts.

## Selective file path

`TrackerRuntime.selectiveDocuments` wraps the existing `SelectiveTransfer` only. `stage(InputStream)` copies a SAF-selected input into the existing private restore-input staging path and persists byte count/hash/source ID plus form ownership. It does not retain/delete the external SAF original. `inspect(id)` reports the existing engine's dependencies/losses/unsupported content. `plan(id, revision, selectedGroups, policies)` persists the exact reviewed base, operation ID and operation hash in FormFiles. It decodes strict UTF-8 and checks the source hash across both streaming passes; it does not retain an extra whole JSON String.

A reopened plan never silently rebases. Explicit `replaceUnappliedReview=true` permits a new review only when no operation with the old ID exists. `apply(id, revision, operationId)` uses the persisted operation ID. Lost responses return/resume that same operation; existing terminal replay does not increment a draft revision. No launch-time apply/resume exists. `resume`, `progress`, explicit `abandon` and `undo(id, expectedToken)` retain the existing atomic groups and conflict rules. Undo refuses after a later Dataset mutation. `export(selection)` writes via existing ExportOperations and its chooser leases, MIME application/vnd.notai.tracker.selective+json. Full JSON replacement and CSV append remain separate, unchanged semantics. UI/SAF launcher and dependency/conflict/partial-result presentation belong to Opus.

## Private copy lifetimes / recovery

Operational maintenance format3 reads1–3; Room11 and full JSON13 remain independent. The nullable manual-time provenance introduced by Room10/full12 is described in START_BACKFILL_CONTRACT.md; operational maintenance remains3. At trusted descriptor cutover all legacy references/tokens remain, with previously global unknown references scoped to every byte group present at cutover, including refused/unregistered groups. Native root unavailable leaves legacy global protection in place. No age/process expiry or guessed abandoned owner is used. Hardlink graph checks continue to protect aliases. This relies on the existing cooperating-writer gate; arbitrary same-UID filesystem interference is not solved by path checks.

Application callbacks persist a UUID Activity lifetime through recreation. FormFiles captures its Activity backend handle owner; saves/read retain exact form references. Finish releases that lifecycle's recorded tokens, preserving active read/apply tokens. Configuration handoff retains ownership; process death does not expire it. Non-Activity consumers use explicit owner IDs and exact thread handoff tokens. Unknown owners remain protected. UUID restore-input staging records exact writer/pending/handoff tokens before I/O, then READY bytes/hash. Consumer acquire replaces only those recorded handoff tokens. Explicit `abandonStage` releases its own interrupted stage tokens, preserves foreign readers and removes no bytes. Selective/schedule workspaces complete their exact leases after durable terminal state.

Full restore previews and rescue previews are AutoCloseable. Cancel/replace a retained preview by closing it; apply protects it and closes only on success. Known private source compatibility readers use the same lifecycle adapter; external originals receive no cleanup authority. Recovery journal3 stores exact source references, writer references and archive IDs. After installed Room readback it durably records completed Dataset hash/session count BEFORE releasing any reference. Pending journal is deleted LAST and directory-synced. Crash reconciliation verifies the installed Dataset and releases only recorded matching tokens; completed resume never replaces the database again. A different source cannot overwrite an unfinished job. Missing/empty installed DB refuses before SQLite open; completion reconciliation uses allowInitialize=false and preserves the pending journal/source leases instead of creating an empty Dataset. Unknown legacy references are not released.

## Sequential integration refinements

Selective selection.excludedOverrides must name existing override keys in selection.seriesIds. A missing override or an override of an unselected series refuses before any domain mutation and cannot produce a false OVERRIDES_EXCLUDED loss. Valid exclusions retain the original occurrence identity; exclusions still belong to explicit selective planning, not full JSON replacement or CSV. Shared Memory/Room fixture coverage is in SelectiveExclusionsScenario.

Projection wake reads now share synchronize's fail-closed boundary: malformed/future authority disarms the existing alarm/receiver, preserves the original exception and journal bytes, and creates no facts or replacement authority.

Legacy inventory cutover does not prove old owners finished. A new exact owner releases only its own tokens; an overlapping legacy witness stays protected. See [LEGACY_OWNER_MIGRATION_REVIEW.md](LEGACY_OWNER_MIGRATION_REVIEW.md) for the exact missing historical origin/census prerequisite and the safe explicit handoff contract. Opus must not turn an UNKNOWN ownership blocker into an unused-copy warning. No automatic legacy token purge was added.
