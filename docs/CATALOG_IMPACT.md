# Единое дерево и словари · реализованный контракт v2

Этот документ заменяет прежнее предложение об отдельных навигационных Group. После уточнения Диониса применяется одно дерево ActivityType: группы и конкретные занятия имеют один nullable parentId. Отдельного дерева папок и второго partOf нет. Количество и глубина узлов не зашиты в код, проверка циклов итеративная.

## История и каталог

Card.activityTypeId — одна необязательная связь. Classification сохраняет activityTypeId и ancestorPathAtWrite от корня до выбранного типа. Можно непосредственно выбрать широкую группу через typeSelection или запустить свою карточку без типа. Reports фильтрует по историческому пути, не текущим parentId. Перемещение меняет будущие записи, включая новый Repeat и Resume; прежние сегменты не перекрашиваются. Архив скрывается в обычном выборе и Start/Switch; явные Repeat/Favorite сохраняют параметры архивной записи и разрешены.

Dataset.children/searchTypes/cardFromType и Tracker.addCatalog работают с данными; aliases не классифицируют записи. addCatalog добавляет отсутствующие определения и сохраняет уже существующие пользовательские названия/связи. Изменение существующего узла — явный saveType; meaningVersion и definition для существующего ID неизменяемы. Новый смысл требует нового ID, поскольку исторический путь хранит ID без отдельного архива версий. Название, aliases, parentId, selectable, archive и подсказки можно менять. Путь записывается внутри транзакции команды, а не принимается на доверии из устаревшей формы UI.

## Независимые оси и величины

Axis хранит ID, meaningVersion, ValueKind (FREE_LABEL/LOCAL_CHOICE), Cardinality (SINGLE/MULTIPLE), значения с собственными ID/версиями и архивом. Facet содержит либо text, либо valueId/valueMeaningVersion. Проверяется тип, кардинальность, существование ссылки. Старые details/tags сохранены отдельно как legacy данные без догадок о соответствии новым осям.

Filter.facets + FacetMatch.ALL/ANY задают AND/OR внутри списка осей. Другие поля фильтра соединяются AND. Пустой список не ограничивает результат. Отчёт сначала выбирает уникальные segmentId; пересекающиеся признаки не добавляют времени. byType и byFacet содержат пересекающиеся суммы, их нельзя складывать в общий итог.

Measurement.value — Decimal: точная неотрицательная десятичная строка, вычисления BigDecimal, никакого Double. Ввод ограничен 1024 символами для защиты разбора; Metric.maxScale ограничивает допустимую точность конкретного поля. Целые длительности остаются Long. Metric определяет ID/версию, NumberKind, каноническую единицу, scope и Aggregation. SUM допускает суммирование; BY_TARGET оставляет значения в report.measurements, не выдаёт общий прогресс. Старые нерегистрированные поля сохраняют прежнюю агрегацию по fieldId/version/unit/scope.

UnitDefinition задаёт размерность и точный положительный factorToBase. Dataset.convert явно переводит совместимые единицы без округления; неограниченная периодическая дробь отклоняется. Например 0.1 mi × 1609.344 = 160.9344 m. Для зарегистрированной метрики периодическая дробь не имеет автоматического обходного пути через исходную единицу. prepareMeasurement возвращает исходный MeasurementDraft и ошибку без записи; пользователь сохраняет черновик и явно вводит допустимое значение в канонической единице либо отменяет ввод. Произвольного округления и скрытого создания другой метрики нет. Значения зарегистрированной метрики сохраняются в её канонической единице. Изменение семантики метрики/оси требует новой версии, коэффициента единицы — нового ID.

## Сохранность

Room schema 2 сохраняет компактную структуру таблиц; новые определения входят в metadata payload. MIGRATION_1_2 преобразует payload всех строк в транзакции Room, валидирует полный граф до UPDATE и не удаляет строки. Destructive fallback отсутствует. Схема 1 сохранена в Git рядом со схемой 2.

JSON formatVersion=2; чтение версии 1 поддержано. Прежний partOf становится activityTypeId с одноэлементным историческим путём: старое дерево было плоским. Никакого сопоставления старых ID новому каталогу по названиям нет. Long превращается в точную строку, включая 9223372036854775807. Неизвестные details, даже с ключами partOf/value, сохраняются буквально. Restore по-прежнему требует preview, проверенный rollback и атомарную замену.

## Предметная приёмка четырёх рисков

- saveType отклоняет смену meaningVersion или definition существующего ID, даже если узел ещё не имеет истории. Это простое единое правило; поправка определения тоже требует нового ID. Оно не пытается определить смысл текста имени автоматически. Новый смысл можно связать с новой карточкой/типом; старые записи сохраняют старый ID. Полный JSON остаётся явно подтверждаемой заменой собственного набора, а не merge каталога.
- suggestedAxisIds/suggestedMetricIds проверяются по словарям при saveType, addCatalog и validate/restore. Подсказка ссылается на ID определения; фактический Facet/Measurement фиксирует выбранную meaningVersion. Неизвестная ссылка отклоняется. Архив и selectable применяются к самому выбранному узлу, без неявного каскада на потомков. Даже raw Classification в start/switch отклоняется, если выбран архивный или невыбираемый тип. Доступный потомок такого родителя разрешён, путь по-прежнему включает родителя. Repeat/Favorite — явные исключения для сохранённого исторического выбора.
- Dataset.prepareMeasurement(MeasurementDraft) — чистая подготовка перед measure. Результат содержит исходные value/unit, либо каноническое Measurement, либо error. При периодической дроби, превышении точности или несовместимых единицах measurement=null, база не меняется. UI сохраняет draft в форме; ядро не обещает переживание смерти процесса для несохранённой формы. Нельзя отправлять в measure исходную единицу зарегистрированной метрики, если она отличается от canonicalUnitId. Допустимое действие — явный новый ввод в канонической единице в пределах maxScale или отмена; никакой автоматической оценки/потери исходной цифры внутри подготовки.
- addCatalog возвращает обычный Change с непустым catalogImport. entries перечисляет каждый ключ с kind/id/meaningVersion/status: ADDED, UNCHANGED или CONFLICT. added/unchanged/conflicts — готовые списки. Конфликтующий локальный объект сохраняется целиком, включая пользовательские имя и parentId; наличие CONFLICT означает, что весь предложенный каталог не применён. Дубликат ключа внутри входа отклоняет всю команду, включая повторы уже существующего ID. Ключ типа/единицы — ID, оси/метрики — ID + meaningVersion. Разные смысловые версии оси/метрики допустимы. Входные определения валидируются также при конфликте; некорректные ссылки/циклы не скрываются под статусом пропуска. Report формируется в той же транзакции, что результат команды.

Новые проверки встроены в прежние три сценария, новая инфраструктура не вводилась. Повторной загрузки частичного seed не было; структура внешнего JSON и будущий адаптер по-прежнему не угаданы.
