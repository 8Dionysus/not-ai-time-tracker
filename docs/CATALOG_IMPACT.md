# Влияние уточняемого каталога — предложение, не реализация

Дионис разделил навигационные группы/подгруппы, запускаемую личную карточку, семантические типы, независимые уточнения, теги и измерения. Конкретное дерево, состав каталога и точный контракт готовит родительская задача. Текущие пять шаблонов и плоский ActivityType не являются завершённой продуктовой структурой. Код этого расширения не добавлялся.

## Минимальные границы

- Навигация: записи Group(id, parentId, label, sortOrder, archived) отдельно от ActivityType. Детерминированный порядок — явный sortOrder, затем устойчивый ID. Проверять уникальность ID, существование parentId, отсутствие циклов. Названия не являются ключами. Кратность размещения карточки в группах и поведение архивирования поддерева надо закрепить в новом контракте; если нужен один путь, nullable groupId карточки проще таблицы many-to-many.
- Навигационное перемещение меняет способ найти карточку, не классификацию прошлых сессий, разрешённые измерения или статистические суммы. Семантическая ссылка карточки на тип и независимые оси остаются явными данными. Не выводить их из пути дерева или похожих названий. Историческая переклассификация — отдельная команда Save.
- Оси: небольшой реестр Axis(id, meaningVersion, label) и Value(id, axisId, meaningVersion, label, archived). Выбор ссылается на ID/версии, сохраняет исторический смысл. Переименование/архивирование не удаляет старые ссылки. Кардинальность выбора (одна/несколько значений) должна быть явно задана; текущая Map<String,String> не объявляется готовым эквивалентом реестра.
- Поля: FieldDefinition(id, meaningVersion, label, unitId, allowedScope, valueKind). Только согласованные простые типы и валидация; никаких формул, языка правил и веток по названию занятия. Определения и выбранные значения входят в полный backup.

## Точные дроби без DSL

Минимальное предложение: хранить числовое значение канонической десятичной строкой, например "2.5" или "72.5", считать через java.math.BigDecimal. Не использовать Double/Float и не округлять при сохранении. Десятичная запятая разбирается на границе ввода, не меняет JSON-формат. Ограничение длины/точности ввода и допустимость отрицательных значений задаются уточнённым контрактом поля. Единица — устойчивый ID, смена смысла — новая meaningVersion; автоматическое преобразование единиц не требуется.

Суммировать только одинаковые fieldId/meaningVersion/unitId/scope, dedup по Measurement.id. Session quantity по-прежнему не копируется в каждый сегмент и не распределяется пропорционально минутам. Отсутствие значения и явный ноль различаются. Целые длительности таймера остаются Long в миллисекундах — изменение касается только измерений.

## Последствия для хранения и миграции

Понадобятся определения групп/осей/значений/полей, ссылки карточек и снимков классификаций, их Room-таблицы и backup-поля. После уже доставленной схемы 1 это оформляется явной миграцией Room и новой версией JSON с поддержкой чтения прежней копии. Long-измерения преобразуются в десятичные строки без потерь. Старые текстовые details сопоставляются только по подтверждённой таблице миграции; неизвестные пользовательские значения нельзя молча классифицировать или выбрасывать.

Перед реализацией зафиксировать: дерево и ID, отдельные семантические типы, определения/версии осей и полей, кратность связей, правила архива и миграцию legacy details. Существующие команды таймера, ревизии, транзакции, контроль времени и безопасный restore переиспользуются. Три сценария расширяются проверкой этих данных, без новой тестовой платформы и без runtime AI.
