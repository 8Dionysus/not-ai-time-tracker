# Единое дерево и словари · реализованный контракт v2

Этот документ заменяет прежнее предложение об отдельных навигационных Group. После уточнения Диониса применяется одно дерево ActivityType: группы и конкретные занятия имеют один nullable parentId. Отдельного дерева папок и второго partOf нет. Количество и глубина узлов не зашиты в код, проверка циклов итеративная.

## История и каталог

Card.activityTypeId — одна необязательная связь. Classification сохраняет activityTypeId и ancestorPathAtWrite от корня до выбранного типа. Можно непосредственно выбрать широкую группу через typeSelection или запустить свою карточку без типа. Reports фильтрует по историческому пути, не текущим parentId. Перемещение меняет будущие записи, включая новый Repeat и Resume; прежние сегменты не перекрашиваются. Архив скрывается в обычном выборе и Start/Switch; явные Repeat/Favorite сохраняют параметры архивной записи и разрешены.

Dataset.children/searchTypes/cardFromType и Tracker.addCatalog работают с данными; aliases не классифицируют записи. addCatalog добавляет отсутствующие определения и сохраняет уже существующие пользовательские названия/связи. Изменение существующего узла — явный saveType. Путь записывается внутри транзакции команды, а не принимается на доверии из устаревшей формы UI.

## Независимые оси и величины

Axis хранит ID, meaningVersion, ValueKind (FREE_LABEL/LOCAL_CHOICE), Cardinality (SINGLE/MULTIPLE), значения с собственными ID/версиями и архивом. Facet содержит либо text, либо valueId/valueMeaningVersion. Проверяется тип, кардинальность, существование ссылки. Старые details/tags сохранены отдельно как legacy данные без догадок о соответствии новым осям.

Filter.facets + FacetMatch.ALL/ANY задают AND/OR внутри списка осей. Другие поля фильтра соединяются AND. Пустой список не ограничивает результат. Отчёт сначала выбирает уникальные segmentId; пересекающиеся признаки не добавляют времени. byType и byFacet содержат пересекающиеся суммы, их нельзя складывать в общий итог.

Measurement.value — Decimal: точная неотрицательная десятичная строка, вычисления BigDecimal, никакого Double. Ввод ограничен 1024 символами для защиты разбора; Metric.maxScale ограничивает допустимую точность конкретного поля. Целые длительности остаются Long. Metric определяет ID/версию, NumberKind, каноническую единицу, scope и Aggregation. SUM допускает суммирование; BY_TARGET оставляет значения в report.measurements, не выдаёт общий прогресс. Старые нерегистрированные поля сохраняют прежнюю агрегацию по fieldId/version/unit/scope.

UnitDefinition задаёт размерность и точный положительный factorToBase. Dataset.convert явно переводит совместимые единицы без округления; неограниченная периодическая дробь отклоняется. Например 0.1 mi × 1609.344 = 160.9344 m. Исходное значение можно оставить в исходной единице для собственного нерегистрированного поля. Значения зарегистрированной метрики сохраняются в её канонической единице. Изменение семантики метрики/оси требует новой версии, коэффициента единицы — нового ID.

## Сохранность

Room schema 2 сохраняет компактную структуру таблиц; новые определения входят в metadata payload. MIGRATION_1_2 преобразует payload всех строк в транзакции Room, валидирует полный граф до UPDATE и не удаляет строки. Destructive fallback отсутствует. Схема 1 сохранена в Git рядом со схемой 2.

JSON formatVersion=2; чтение версии 1 поддержано. Прежний partOf становится activityTypeId с одноэлементным историческим путём: старое дерево было плоским. Никакого сопоставления старых ID новому каталогу по названиям нет. Long превращается в точную строку, включая 9223372036854775807. Неизвестные details, даже с ключами partOf/value, сохраняются буквально. Restore по-прежнему требует preview, проверенный rollback и атомарную замену.

При поступлении данных нужен небольшой явный адаптер/проверка, без изменения общей модели.

При правке заметки/времени с прежним activityTypeId сохраняется прежний исторический путь. Для явного пересчёта по текущему дереву передать reclassify=true. UI сначала вызывает previewCorrection(sessionId, edits, note, reclassify): он не пишет в базу и через preview.reports возвращает старые/новые суммы на одном asOf. После подтверждения — applyCorrection(preview), с сохранённым Token и одношаговой Undo. Отмена формы не требует команды. Прямая correctSession остаётся командой Save; массовой переклассификации нескольких сессий нет.
