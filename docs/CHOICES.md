# Поиск, навигация и предложения из истории

Документ описывает локальный read API готового каталога и личной истории. Основной интерфейс, телеметрия, сеть и фоновый индексатор в него не входят.

## Единая граница чтения

```kotlin
val choices = tracker.view().choices() // сохранить immutable view на время ввода/страниц
val query = ChoiceQuery(text = "coffee", kinds = setOf(ChoiceKind.TYPE, ChoiceKind.CARD))
val first = choices.search(query, pageSize = 30)
val second = first.next?.let { choices.search(query, cursor = it, pageSize = 30) }
val roots = choices.search(ChoiceQuery(kinds = setOf(ChoiceKind.TYPE), scope = CatalogScope.ROOTS))
val children = choices.search(ChoiceQuery(kinds = setOf(ChoiceKind.TYPE), scope = CatalogScope.CHILDREN, parentId = groupId))
val recent = choices.suggestions(SuggestionQuery(enabled = true))
val frequent = choices.suggestions(SuggestionQuery(
    enabled = true, order = SuggestionOrder.FREQUENT_RECORDED,
    window = HistoryWindow(startEpochMs, endEpochMs)
))
```

`Tracker.choices()` — сокращение того же пути. Размер страницы 1–100, по умолчанию 30 для поиска/20 для предложений; query до 256 символов. `total` — весь подходящий состав, `next` позволяет прочитать его полностью. Лимит страницы не является top-N каталогом. GROUP и архивные результаты могут быть прочитаны/открыты для навигации и настройки; они не становятся запускаемыми.

Курсор держит готовый порядок результатов и относится к **тому же ChoiceView и точному запросу**. Следующие страницы не пересобирают сортировку. Другой view/запрос получает STALE с snapshot; старый view может закончить свои страницы без смешивания ревизий. При изменении текста/снимка UI освобождает старые cursors. Это объекты памяти, не переносимые bookmarks. Индексы и результаты не сериализуются.

## Что возвращается

`ChoiceEntry`: устойчивый id результата, kind, sourceId, заголовок, текущий путь с ID/названиями/флагами, полный `Classification`, note только у исторического источника, availability и ссылки на исходные session/segment. `ChoiceHit.matches` объясняет поле и силу совпадения; `suggestion` содержит причину, окно, число уникальных сессий и последнее записанное окончание.

TYPE/CARD/FAVORITE имеют ID с префиксом вида + исходным ID. HISTORY имеет детерминированный SHA-256 ключ точного варианта Classification: учитываются исходные имя/путь/ID, details, tags и facets; порядок map/set/facets канонизирован только для ключа. Сохранённые данные не нормализуются и не переписываются. Representative sourceId может поменяться при новой записи того же варианта, а id варианта остаётся тем же. Одинаковые названия разных ID не сливаются.

Новый API не создаёт другой механизм запуска. Для выбранного варианта используются существующие `start(page.token, entry.selection, entry.note)`, `switch` или `labelCurrent`. `hit.entry.canStart` означает пригодность классификации; допустимость команды при текущем RUNNING/PAUSED/Focus и stale token всё равно проверяет ядро. Повтор целой сессии остаётся `repeat`; предложения могут представлять отдельный вариант её сегмента, поэтому для него передаётся именно возвращённый selection. Длительность, количественный прогресс и история не копируются.

Карточка даёт живые defaults; Favorite остаётся сохранённым snapshot-вариантом, не переименован в live item favorite. Исторический вариант сохраняет tags/details/facets и note выбранного источника. Текущие имена карточки/типа и aliases могут помочь найти старый вариант, но совпадение помечено CURRENT_CARD_NAME/CURRENT_TYPE_NAME/ALIAS; historical selection остаётся прежним. Новый Start, как и раньше, записывает текущий путь типа; старые записи не переклассифицируются.

## Поиск и навигация

Глобальный scope ALL — по умолчанию, без неявного ограничения текущей папкой. ROOTS/CHILDREN/SUBTREE задаются явно. Для TYPE children — непосредственные дети; для личных объектов — непосредственно выбранный тип. Path отличает одноимённые узлы. Архив родителя не архивирует потомка: сохранена node-local семантика ядра.

Индекс хранит NFKC, Locale.ROOT lowercase и нормализованные пробелы отдельно от оригинала. Диакритика не удаляется, транслитерация/fuzzy/автоклассификация не вводятся. Разные языки находят явно заданные aliases. Порядок: точное совпадение, prefix, contains, затем запрос из слов, совпавших в разных индексированных полях; внутри силы — поле, далее FAVORITE/CARD/HISTORY/TYPE, нормализованное имя и ID. Для пустого поиска — вид, имя и ID. Причина содержит исходный текст совпавшего поля.

Индексируются имена, aliases и именованный контекст сохранённых вариантов. Произвольные notes/details/facet values не превращаются в скрытый полнотекстовый поиск. Фасеты остаются параметрами выбранного варианта; отдельные подсказки значений и pins — будущая работа.

Существующие `Dataset.children`, `ancestorPath`, операции карточек/Favorite/Repeat не дублируются новыми мутациями. Старый `Dataset.searchTypes` оставлен deprecated compatibility helper со своим прежним contains; новый UI использует paged API.

## Предложения из записанной истории

Suggestions по умолчанию выключены (`enabled=false` возвращает пустую страницу без построения истории). Включение — явный локальный read-запрос; нет обязательного шага перед Start. В них входят только определённые положительные сегменты **завершённых сессий**, сгруппированные по точному варианту. Текущая сессия управляется через Snapshot/Resume, не предлагается как второй запуск.

RECENT_RECORDED сортирует по последнему записанному end; FREQUENT_RECORDED требует явное полуоткрытое окно и считает уникальные sessionId с подходящим сегментом, пересекающим его. Паузы/два одинаковых сегмента одной сессии не удваивают частоту. Сессия с разными вариантами может участвовать в каждом — эти числа не являются общей суммой сессий. Frequency ties: последний записанный end, имя, ID; recent ties: имя, ID.

Это **исторические недавние/частые варианты**, не журнал нажатий Start. Коррекция дат может изменить их порядок; Undo его восстанавливает. Настоящий launch-recents M26 требует отдельной последовательности успешных запусков и не заявляется реализованным. Никаких скрытых 8-item caps, автоматического закрепления или переупорядочивания Favorite нет. Весь соответствующий состав доступен страницами.

Архивная карточка, архивный тип и selectable=false исключены из предложений; поиск с includeArchived может показать их как недоступные. Неуточнённый вариант остаётся пригодным для запуска. Сохранённый явный `repeat`/`startFavorite` сохраняет прежнюю возможность исторического архивного повтора; read API не превращает её в автоматическую рекомендацию.

## Лёгкость и инвалидация

На Tracker есть один небольшой ChoiceCache с отдельными нормализованными частями: каталог, личные карточки/Favorite, завершённая история. Построение ленивое, только по запросу соответствующего вида. Нормализованные строки/пути переиспользуются на каждой букве и тике, а не пересчитываются заново. Сканирование уже подготовленных полей и сортировка по новому запросу остаются линейной/сортировочной работой; тяжёлый сервис/FTS и сложный LRU не добавлены.

Изменения типов инвалидируют каталог, cards/Favorite — личную часть, сегментов завершённых сессий — историю. Изменение только active session или заметки не требует нормализовать завершённую историю; возвращённая note читается из нового immutable view. На чужом Room generation/restore содержимое сравнивается, чтобы равные справочники не строились снова. При изменившихся коллекциях проверка равенства/проекция может сканировать историю один раз на новую ревизию, но не каждый тик/букву. Полностью новый Tracker/процесс строит нужные части заново, без дискового кэша.

`indexStats()` — неперсистентные счётчики построений для проверки интеграции, не аналитика пользователя. Пагинация ограничивает выдаваемые UI-объекты; внутренний порядок запроса включает весь результат. UI освобождает старый view при смене задачи/запроса, не хранит бесконечную цепочку старых cursor.

## Проверка и совместимость

Текущие Room11 и JSON13/read1–13: read API выводится из переносимых данных; исходный контракт выбора вводился при Room5/JSON7. Актуальные ограничения приложения — [состояние проекта](ACCEPTANCE_GAPS.md).

Те же 3 сценария × Memory/Room: импорт полного корпуса, полный обход 1923 типов (1918 + 5 seed) страницами, Unicode alias, одноимённые пути/группы, карточка vs Favorite vs исторические параметры, два сегмента одной сессии и частота, переименование/архив/group flags, исправление/Undo, unclassified, перенос и повтор с details/tags/facets/note. Проверяется отсутствие переиндексации на 50 запросах/тиках и active-only изменениях, STALE чужого cursor, отсутствие мутаций от чтения. Проверка settings/configureFocus уточняет намеренную разницу defaults/плана активного запуска.

[Сохранённые результаты Choices](../evidence/choices-v16/verification.json) включают небольшой JVM-замер полного каталога. Текущие результаты — [VERIFICATION](VERIFICATION.md). JVM-замер не является p95 ввода на телефоне, проверкой TalkBack или пользовательского макета.

Пустые nonselectable группы исключены из обычного выбора; `includeArchived=true` сохраняет полный технический обход всех ID. `latestRecorded()` использует recorded end/start/id, а не порядок добавления, и возвращает sourceSessionId/sourceSegmentId. Явный Repeat и Favorite используют сохранённую классификацию, включая архивные параметры.
