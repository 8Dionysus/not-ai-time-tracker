# Необязательные цели

Цели живут в `Dataset.goals`, по умолчанию список пуст. Функция локального ядра. Без streak, наград, штрафов, уведомлений, ИИ, автоматического Start/Stop и фоновых задач. История — единственный источник прогресса; производные суммы не сохраняются.

## Операции для UI

```kotlin
val goal = Goal(
    name = "Языковая практика",
    metric = GoalMetric.DURATION_MS,
    target = 30 * 60_000L,
    direction = GoalDirection.MINIMUM,
    period = GoalPeriod.WEEK,
    zone = "Europe/Berlin",
    filter = Filter(activityTypeId = "language")
)
val saved = tracker.saveGoal(token, goal) // создание или замена по устойчивому id; доступен Undo
val progress = tracker.goalProgress(goal.id) // текущий период в зоне цели
val historical = tracker.goalProgress(goal.id, LocalDate.parse("2026-03-29"))
val disabled = tracker.saveGoal(saved.state.token, goal.copy(enabled = false))
tracker.deleteGoal(disabled.state.token, goal.id) // также Undo
```

Все команды используют существующую транзакционную границу и expected token. Отмена формы ничего не пишет. `TrackerView.goalProgress` позволяет считать по одному зафиксированному состоянию; каждый вызов захватывает один now. При нескольких связанных расчётах можно передать один `Moment` в `Goals.progress(data, now, id, date)`.

`enabled=false` сохраняет определение и позволяет явно посмотреть прогресс; UI по умолчанию выбирает enabled цели. Ни включённые, ни отключённые цели сами не запускают вычислительные циклы. Копирование карточки не копирует цель: её cardId остаётся исходным. Архивирование карточки/типа не удаляет цель или историю. Редактирование определения пересчитывает представление по существующей истории, а не создаёт журнал старых версий цели.

## Значения и периоды

- `DURATION_MS`: целое записанное время из `Reports.report`, пересечение [start,end), та же фильтрация и распределение, что в истории/CSV.
- `SESSION_COUNT`: число уникальных sessionId с положительным подходящим записанным временем в выбранном периоде. Сегменты и паузы не умножают сессию. Активная или paused сессия включается, отдельно отмечается незавершённой.
- `MINIMUM`: `MINIMUM_PENDING` либо `MINIMUM_REACHED` по записанным данным.
- `LIMIT`: `WITHIN_LIMIT` либо `LIMIT_EXCEEDED` по записанным данным. Лимит не блокирует таймер.
- `DAY`: локальные сутки; `WEEK`: ISO-неделя с понедельника; `MONTH`: календарный месяц; `FIXED`: явные ISO-даты `startDate` и `endDateExclusive`. Для остальных периодов эти поля должны быть null.

`zone` — отдельная сохранённая IANA-зона цели, не неявная зона телефона и не изменяемая автоматически зона общего отчёта. Границы строятся через календарь: весенний день может иметь 23 часа, осенний — 25. Пределы полуоткрытые, конечная граница исключена. Нельзя задавать неположительную цель, пустые/повторные ID, неизвестную зону/ссылку или неверный фиксированный период. Запросы вне поддерживаемой временной области возвращают ошибку.

**Политика количества занятий:** сессия 23:59–00:01 участвует один раз в каждом из двух дневных периодов, но один раз в охватывающей неделе. Это число сессий, участвовавших в периоде, а не количество нажатий Start. Дневные количества нельзя складывать для получения уникального недельного количества. Ядро пересчитывает уникальные ID для каждого окна.

`Filter` общий с отчётами: cardId, activityTypeId по сохранённому историческому пути, details, tags, facets ALL/ANY. Несколько совпавших признаков не дублируют время/сессию. Перемещение типа не переписывает классификацию старых сегментов. ANY поддерживает альтернативные значения одной оси.

## Прогресс по записанным данным

`GoalProgress` отдаёт `window`, `asOf`, `actual`, позицию BELOW/AT/ABOVE, `recordedStatus`, `remaining` до порога и `excess` над ним, `incompletePeriod`, `hasRecords`, ID завершённых/незавершённых сессий и неопределённых сегментов. Статусы — описание записанного объёма, не оценка человека и не обещание окончательного результата периода. При incomplete/uncertain UI сохраняет эти признаки; отсутствие записей не доказывает отсутствие деятельности.

Неопределённые интервалы не получают выдуманной календарной привязки или количества. Как в Reports, список unresolved консервативен: подходящий неопределённый сегмент может требовать решения даже без доказательства его попадания в конкретное окно. Импорт активного хвоста оставляет его для `resolveTail`, а не превращает asOf в конец. Коррекция, Undo, импорт и восстановление сразу отражаются в следующем расчёте, без отдельного пересчёта сохранённого прогресса.

## Хранение и совместимость

Room schema 5: небольшой список определений хранится в уже существующем metadata payload и транзакционно проверяется чтением обратно. У старого payload без goals читается пустой список. Не добавлялись отдельный сервис/таблица/индекс прогресса. Как и остальные свойства, вложенные фильтры защищены от изменения через исходные коллекции и casts.

Полная копия — JSON **7**, reader принимает **1–7**. Goals введены в формате 6: поле обязательно в форматах 6/7, ID цели обязателен. Копии 1–5 без целей читаются с пустым списком. Restore preview показывает число целей; полная замена и откатная копия включают их. Неверная цель или повреждённый файл не меняют старую базу. CSV остаётся экспортом истории, не заменой полного JSON. Старые APK/читатели не обязаны читать новый формат/payload; downgrade не поддерживается и не должен использоваться как перенос данных.

Пример полного проверенного JSON: [goals-example.json](../evidence/goals-v14/goals-example.json). Это тестовые данные, не личная история пользователя. При восстановлении он полностью заменяет локальный dataset.

## Проверка и остаток

Те же 3 сценария × Memory/Room: создание целей → активное время через полночь → пауза/Resume → Stop → коррекция/Undo → новый активный хвост → переоткрытие → JSON/restore/recovery. Проверяются 23/25-часовые сутки, недельные/месячные/фиксированные границы, перенос сессии за границу периода и обратный Undo, уникальный session count, оба направления, фильтр без совпадений, независимая зона цели, неверные/неполные JSON, disable/delete/Undo, защищённость коллекций. V13 сценарии, каталоги, поверхности и миграции сохранены.

Сохранённые результаты введения Goals: [verification.json](../evidence/goals-v14/verification.json). Результаты текущего общего набора — [VERIFICATION](VERIFICATION.md).

API целей доступен ядру; удобный экран управления целями отсутствует. Физическое устройство не проверено. Параллельный учёт, автоматический запуск и награды не являются частью этого API.
