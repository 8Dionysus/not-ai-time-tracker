# Календарь истории, группы и входные черновики

API проецирует уже записанную историю и готовит временные формы. Внешние адаптеры CalendarProvider/PROCESS_TEXT описаны в [Android-адаптерах](BACKEND_V13.md); они не записывают историю до явного действия пользователя.

## Календарь существующей истории

```kotlin
val view = tracker.view()
val calendar = view.calendar(LocalDate.parse("2026-03-01"), 31, filter, "Europe/Berlin")
val csv = Csv.export(calendar.window)
val groups = calendar.window.groupSimilar()
```

`CalendarHistory` содержит token ревизии, `window: Report` и дни. Размер страницы 1–62 календарных дня; следующий месяц запрашивается явно. Исходные timestamps не изменяются. Один вызов получает один Moment и один раз материализует сегменты; все дневные строки используют общий с Reports алгоритм пересечения и целочисленного распределения времени. Граница дня вычисляется через ZoneId/LocalDate, включая DST. Сумма дней равна `window.recordedMs`; обычный `Reports.day` даёт те же строки и суммы при том же now/фильтре/зоне.

`CalendarDay` содержит дату, точные границы, строки ReportRow с segmentId/sessionId, recordedMs и incomplete. Строка, пересекающая полночь, отображается в нескольких днях с тем же segmentId и разными отсечёнными интервалами. Это представление, не новые сегменты. Пустой день означает отсутствие записанного времени, не доказательство отсутствия активности. Статус сессии доступен через Session по sessionId из того же view; отдельная модель календарных сессий не вводится.

Неопределённые интервалы находятся только в `window.unresolved`: точный день им не назначается. Как в обычном Report, это все подходящие неопределённые сегменты, а не доказанно попавшие в окно. Количества находятся один раз в `window.measurements`; целые SESSION/SEGMENT количества не размножаются по дням и не распределяются пропорционально времени. `window` прямо пригоден для CSV и обычной статистики.

Целиком пропущенная местная дата, например Pacific/Apia 2011-12-30, возвращает INVALID_INTERVAL в day/calendar. Многодневная страница через такую дату тоже отклоняется с указанием даты/зоны; диапазон не сокращается молча. Можно запросить страницы до и после пропуска. Обычные DST-дни 23/25 часов поддерживаются.

Календарь — явный запрос истории, не работа на каждом тике. Материализация O(segments); отсечение по дням O(days × segments), days ≤ 62. Нет новой SQL-таблицы, фонового индексатора или кэша всех месяцев. Большая история и реальная прокрутка на телефоне ещё требуют измерений.

## Группировка похожих записей

`Report.groupSimilar()` группирует **точно одинаковый сохранённый вариант**: card/type IDs, историческое имя/путь, details/tags/facets. Это тот же canonical key и `history:SHA256` ID, что у исторических предложений Choices. Порядок maps/sets/facets не создаёт лишние группы. Имена сами по себе не объединяют разные карточки; архив/переименование не перекрашивают сохранённую классификацию.

Группа содержит исходные строки, selection, время и число уникальных сессий в выбранном окне. Несколько сегментов одной сессии не удваивают её счётчик; сессия с разными вариантами может участвовать в нескольких группах. Notes остаются у строк, количества — у Report. Группировка не сливает/редактирует историю, не присваивает тематику по похожести текста. Для более широкого среза уже есть byCard/byType/byFacet; дублирующий механизм не добавлен. Порядок групп — последний конец записи по убыванию, затем ID; строки — start/segmentId.

## Текст и событие: форма до явного действия

```kotlin
val fromText = EntryDrafts.selectedText(selectedText) // полная строка в note, неуточнённая классификация
val fromEvent = EntryDrafts.event(
    title = eventTitle,
    interval = DraftInterval(startEpochMs, endEpochMs),
    selection = chosenSelection,
    reference = providerOccurrenceReference
)
// UI может редактировать copy(selection=..., note=..., interval=...) или просто закрыть форму.
tracker.startDraft(expectedToken, fromEvent) // Start сейчас, без переноса плановой длительности
tracker.recordDraft(expectedToken, fromEvent) // только после подтверждения показанного интервала
```

Это две альтернативные команды, не последовательный рецепт. `EntryDraft` — временная форма поверх Classification/note/интервала; не Session, не хранилище будущих событий. Конструкторы ничего не пишут. Текст/название события сохраняется целиком в note, без автоматического выбора карточки, NLP-разбора «завтра/15 минут» или усечения; допустимо 1–16384 символов с непустым содержимым. Выбор занятия — существующий Choices/cardSelection/typeSelection, явно переданный вызывающей стороной.

`startDraft` делегирует обычному Start: новый ID, текущее now, выбранные параметры и заметка; предложенный интервал игнорируется. Уже активный таймер, stale token и недопустимая классификация проверяются тем же ядром. Никакого второго таймера или автоматического Switch.

`recordDraft` делегирует manual, создаёт новую завершённую сессию/сегмент лишь после явного действия вызывающего UI. Нужен точный положительный интервал без пересечения и без будущего конца; доступны обычные Change/пересчёт и Undo. Предлагаемое событие не означает фактически выполненную работу. Повторное копирование не является upsert/идемпотентным импортом: то же перекрытие отклоняется; изменённый непересекающийся интервал — самостоятельная запись.

Для all-day/неизвестного времени передаётся interval=null: запуск сейчас доступен, историческая запись требует ввода точных границ. Местные даты нельзя самовольно превратить в 24 часа выполненной работы. Адаптер должен передавать конкретное вхождение повторяющегося события, а не правило серии. sourceReference — непрозрачный контекст формы до 1024 символов: ядро его не открывает, не использует для дедупликации и не сохраняет в истории/JSON. Событийная модель провайдера, recurrence engine и календарная синхронизация не добавлены.

Выделенный текст и title могут быть приватными. Форма остаётся внутри приложения; note не входит в безопасную подпись lock screen и не пересылается по сети. Android PROCESS_TEXT принимает только явно присланный текст, CalendarOccurrences читает только явно выбранное вхождение после opt-in и READ_CALENDAR.

Обе команды проверяют EntryDraft после редактирования, включая прямой конструктор и copy. note=null означает явное удаление заметки; непустая строка сохраняется целиком, предел 16384 UTF-16 code units (Kotlin String.length), пустая/пробельная строка отклоняется. sourceReference допустим только для CALENDAR_EVENT: null либо 1–1024 code units без ISO control characters. Trim, усечение и нормализация не выполняются. Неверная форма не изменяет базу.

## Проверки и ограничения

Общий `localEntryLifecycle` входит в существующий smallHistoryAndExport и исполняется на Memory и Room. Проверяет отсутствие записи при черновике/отказе, точное сохранение текста и параметров, future/overlap/stale, Start-now, pause/resume, 23/25-часовые дни, единство строк/сумм с Reports и CSV, отдельные IDs одноимённых карточек, количество сессий без удвоения, 20 страниц один раз, correction/Undo, реальное JSON replacement на чистой базе и неприписываемый дню хвост после reboot.
