Размер 12 396 625, SHA-256 239faf8ccddf1102b5d5834fc3304d2a0e2abc013a008b1eb83e1a821dd4ab19. 238 непрерывных окон покрыли 237 183 строки; дополнительный конечный LF не добавлен. ## Граница ядра

ResearchCatalog.read(bytes, expectedSha256) проверяет хеш до разбора, поддерживаемую схему 0.5, уникальные source-qualified ключи, соответствие sourceToWorkingNode и обратных ссылок узлов, все researchPath по единственной parent-цепочке без фиксированного предела глубины. Reader различает ResearchSource, ResearchNode, ResearchKind, ResearchOutcome и сохраняет исходный JsonObject и исходные байты; поля доказательств не удаляются при проекции.

Результат ResearchPlan — подготовка, не публикация и не запись в базу. plan.sourceBytes возвращает точные исходные байты. plan.outcomes содержит указатель JSON pointer, тип элемента, ключ, disposition, причину и runtimeId, когда он есть. candidateIds и axisCandidateIds показывают выразимые кандидаты. vocabulary(selectedIds, selectedAxisIds) требует явного выбора, добавляет проверенных родителей и не подменяет их другими. Порядок результата не зависит от порядка выбора.

plan.apply(tracker, token, selectedIds, archive, selectedAxisIds) сначала сохраняет исходник через ResearchArchive и проверяет чтение обратно по SHA-256, затем вызывает единый Tracker.addCatalog. FileResearchArchive — локальное хранилище по хешу с временным файлом, fsync, атомарным перемещением и синхронизацией каталога. Использовать приватный каталог приложения; UI не добавлялся. Если источник повреждён или Token устарел, база не изменяется. Успешно сохранённый исходник может остаться в архиве после отказа команды; это неизменяемое доказательство, не запись времени.

В ActivityType и Axis добавлены researchOrigins: хеш полного пакета, имя/хеш исходного файла, исходный ID и указатель внутри пакета. Runtime JSON сохраняет эти ссылки, но НЕ встраивает 12 MiB исследовательского корпуса. При переносе полного исследовательского доказательства нужно отдельно перенести файл из ResearchArchive; он включён в эту поставку. Обычная JSON-копия остаётся полной копией пользовательских карточек/истории/словарей/настроек и не обещает включать внешние исследовательские документы. Экспорт теперь formatVersion=3; decode читает 1, 2 и 3. Room остаётся версии 2: новые поля payload необязательные, старые строки читаются с пустыми origins; SQL-структура не меняется.

## Фактическое покрытие

- Все 1584 исходные записи и 1587 рабочих узлов сохранены. Никакого сокращённого seed вместо корпуса нет.
- Шесть конфликтов seed/work-learning сохранены source-qualified: job_search, writing.journal и language.lesson используют явно указанное пакетом повторное применение канонического ID; writing.draft → writing.compose_draft, writing.correspondence → writing.compose_correspondence, language.conversation → language.conversation_exchange получают отдельные рабочие ID. Обе исходные формулировки остаются в корпусе. Alias education.take_notes → learning.take_notes учтён отдельно, не выдан за седьмой новый смысл.
- Рабочая проекция для явно выбранного импорта: 1584 типа, из них 1496 selectable. Это НЕ 1584 различных действия: здесь есть группы и предложенные подвиды. Невыбираемые группы нужны для пути и не запускаются через обычный Start.
- Три узла не превращены в ActivityType: kinship_care_context (контекст), event_log (схема событий), passive_supervision_concurrent (параллельная ответственность, требующая отдельного явного выбора основного действия). Исходники и решения сохранены с конкретной причиной.
- Проверены все 102 записи осей и ledger всех 760 вхождений значений. Сопоставление идёт по исходному файлу/оси/полю/индексу и точному original value; одинаковые названия не схлопываются. 5 retain_concept/free_label осей с явной кардинальностью преобразованы в отдельные source-local IDs research:<inventory>:<axisId>. Остальные 97 осей сохранены с диагностикой требуемого решения схемы. Значения-примеры не стали обязательными закрытыми списками; 760 исходных вхождений остались доказательствами, а не автоматически созданными AxisValue.
- Все 20 метрик и 24 бытовых количественных кандидата имеют результат: два упоминания длительности ссылаются на существующий механизм Segment; остальные не создают дополнительные минуты. Объект, событие, роль величины, scale, derived quantity и видимость не подменены безконтекстным числом.
- 10 956 проверяемых исходных ссылок: 6112 parent/relation и 4844 source-local axis. В фактическом корпусе они разрешились; слой доказательных отношений не становится вторым деревом или дополнительным временем. Ссылки на внешние документы/источники сохраняются отдельно и не объявляются проверенными по отсутствующим байтам.

Полный ledger: evidence/research/adapter-outcomes.json. Сводка: evidence/research/summary.json. Проверенное выбранное VocabularyData: evidence/research/runtime-vocabulary.json. Каждый top-level раздел также имеет PRESERVED_ONLY outcome: глубокие поля доказательств сохранены целиком, но не интерпретируются как runtime-правила. Это не утверждение, что все внешние ссылки/аналитические счётчики проверены. Проверяемые manifest counts сверены; остальные получили отдельную диагностику declared-count.

Полный корпус участвует в прежнем smallHistoryAndExport, поэтому те же 3 Core и 3 Room/Robolectric сценария проверяют реальный объём, а не выборку. Проверены точные исходные байты, шесть ID-решений, все пути, детерминированный выбор, полный импорт выбранной проекции в Room, повторный импорт без добавлений, конфликт с локальным иным смыслом, сохранение истории и provenance через JSON export/restore, запуск без классификации после импорта, отказ при повреждённом evidence archive и неверном пути/хеше. Прежние регрессии v1/v2/rollback сохранены. Сформирован APK 0.3.0; устройство не проверялось.

## Точный остаток, без подмены предметной работы

Отдельные README/compatibility, identity-resolution и аналитические файлы представлены в JSON именами/хешами, а не полным содержимым. Поиск отдельных compatibility/identity файлов в Library не дал результатов; их прочтение не заявлено. В частности, число 357 внешних междоменных отношений из manifest не заменяется найденными локальными relationship-полями и не считается независимо подтверждённым без соответствующего документа.

Следующее предметное решение: для axis.mode составная метка может связывать действие и модальность; рекомендуемый путь — явная составная выборка с source-qualified компонентами и версиями, сохраняя исходную метку, а не один новый глобальный valueId по названию. Для параллельного наблюдения следует отдельно предложить человеку основное действие наблюдения либо контекст ответственности; не создавать вторую аддитивную длительность и не переопределять исходный ID. Для quantity.pages нужны объект/издание и count-vs-position, для событий ухода — идентичность события; текущая scalar Measurement этого контекста не выражает. Эти элементы остаются в ledger, а не исчезают.

Продуктовый bootstrap автоматически не заменён: адаптер доступен для вызова ядра с явным выбором. Нет UI, массовой переклассификации истории, сервера, модели, credentials или новых исполнителей. Полная предметная завершённость и полная runtime-публикация каталога не заявлены.
