# Готовый каталог

Приложение получает подготовленный `VocabularyData`, а не исходные исследования. В `catalog/` находятся три файла: `manifest.json`, `runtime-catalog.json`, `compatibility.json`. Manifest закрепляет версию, размер и SHA-256 каждого payload. `ReadyCatalog.read` проверяет их, ссылки и структуру, затем возвращает неизменяемый словарь. Неверный пакет не устанавливается.

Текущий пакет 0.9.3.0 содержит 1919 типов и 337 осей. Это редакторский шаг поверх 0.9.2.0. Переводы в `catalog/locales` и `catalog/editorial` получили короткие названия, сделанные по коротким русским («Video editing» вместо «Edit video and assemble the sequence or timeline»); прежняя длинная подпись осталась в aliases, поиск её находит. Источник — `localization/catalog-short/` (строка на тип в порядке `order.json`, 11 языков), сборка — `scripts/catalog_short_labels.py`. Носители языка эти короткие названия ещё не вычитывали. 41 занятие, неуместное в трекере времени, поставляется архивным: интимные карточки, мрачные и секундные профессиональные микрошаги (эвтаназия животных, проверка возраста покупателя, снятие залога и т. п.), лотерея и дубли «Казино», явные дубли соседних пунктов (три квилта, три хендбайка, два «быстрых» сна, «Личные сообщения» рядом с «Личной перепиской» и др.). «Генеалогия» переехала в самообразование, «Градостроительство» — в право и госуправление. Описания, ID, selectable и meaningVersion не менялись; отпечаток смысла изменился только у двух переехавших записей.

Предыдущий шаг 0.9.2.0 дал 1850 занятиям короткие русские названия, переставил 62 раздела и добавил «Короткую разминку»; его правила остаются в `compatibility.json` вместе с шагом 0.9.1.3, поэтому старые установки обновляются за один раз. Частный файл редакторских поправок не включён в APK или дерево репозитория. Предыдущий готовый словарь присутствует только в сжатом тестовом fixture для проверки миграции.

## Новая и существующая установка

Новая база создаётся с полным готовым словарём и локальной зоной устройства. Пять технических bootstrap-типов сохраняются для совместимости старых копий и тестов; они не являются начальным пользовательским каталогом новой установки.

Существующая база не перезаписывается при запуске. `CatalogImports.prepare()` показывает added/updated/unchanged/conflicts; отмена ничего не пишет. `apply(preview)` требует исходный token, проверяет пакет и меняет словарь атомарно. История, карточки, избранное, aliases, архивность и личные названия сохраняются. Повтор не создаёт дубликатов. Пустая nonselectable группа скрыта из обычного выбора, её ID сохранён для совместимости.

## Совместимость

Технические origin/hash-поля не определяют семантическую идентичность. Стабильное значение с новым provenance остаётся unchanged; локальное представление не заменяется.

Изменённое описание принимается только для явно перечисленного правила: текущий смысл совпадает с `fromMeaningSha256` (или одним из `alsoFromMeaningSha256` для более старых установок), новый — с `toMeaningSha256`, прочие смысловые поля совпадают. Уже установленный новый смысл также принимается. Перенос в другой раздел допускается только с `parentMove: true`; без него это конфликт. `archive: true` убирает из выбора тип, который каталог поставляет архивным, — только если ни одна запись пользователя (карточка, избранное, план, цель, отчёт, история, удалённое) и ни один дочерний тип не ссылаются на его ID, а имя и aliases не изменены пользователем; иначе тип остаётся живым. Без такого правила установленный тип не архивируется. Штатное имя обновляется только при совпадении хеша старого стандартного имени (`previousDefaultNameSha256` или `previousDefaultNameSha256s`) и тогда берёт из каталога и aliases, чтобы перевод продолжал совпадать; личное имя и личные aliases сохраняются.

Прошлые записи хранят путь в дереве на момент записи (`ancestorPathAtWrite`), поэтому `Report.byType()` и фильтр по типу считают их по старому пути. `Report.byCurrentRoot(types)` считает каждую запись один раз под текущим корнем её прежней области: этим пользуются обзор и текст «Поделиться», чтобы после переезда время программиста было в «Работе», а не в исчезнувшем корне. Произвольные смысловые изменения конфликтуют. Обычный публичный `addCatalog` имеет строгую политику и не получает редакторских исключений.

Ядро не содержит известных пар исследовательских SHA, требований к профессиям или фиксированного числа типов. Счётчики и проверка точного редакторского delta принадлежат тестам и подготовке поставки.

Материалы исследований удалены из текущего дерева после проверки внешних архивов. Исходная история Git сохранена; подготовка не лицензирует исходные материалы заново.
