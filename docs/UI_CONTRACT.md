# Контракт интеграции интерфейса

Действующий контракт для Android-оболочки 0.9.1 и Kotlin-ядра. Room schema 4; JSON export 7 и read 1–7. Предыдущие схемы относятся к [истории реализации](history/ACCEPTANCE_GAPS_through_v15.md), а не к текущим инструкциям.

## Runtime, чтение и команды

Получить `TrackerRuntime.get(applicationContext)` на `Dispatchers.IO`. Команды, backup и обращения к хранилищу блокирующие; выполнять их на IO. Все Android-поверхности используют тот же runtime.

`tracker.views: Flow<TrackerView>` публикует сохранённые ревизии. `tracker.view()` получает один неизменяемый снимок данных; `view.snapshot()` рассчитывает текущий таймер по Clock без чтения базы, полного прохода истории или записи секунд. UI сохраняет view на время связанного расчёта и заменяет его после нового emission. `tracker.snapshots` также доступен, но для связанных данных/отчётов предпочтителен `TrackerView`.

Во время видимости экрана UI может обновлять текущий snapshot раз в секунду. Наблюдение и ticker ограничиваются lifecycle; перерисовка не требует фонового сервиса. Отчёт — отдельный запрос по ревизии. Один `Moment` используется для всех частей связанного расчёта.

Обычная команда формы принимает `Token(datasetId, revision, sessionId)` из показанного пользователю состояния. Старое нажатие нельзя повторять с новым token автоматически. Проверка выполняется внутри транзакции; `STALE` содержит актуальный `currentState`. Даже изменение настройки делает старую форму устаревшей. Таймерные поверхности используют отдельный TimerTarget(datasetId, sessionId, epoch, barrier): несвязанная настройка его не меняет; переход таймера и restore инвалидируют. Внутри той же транзакции проверяются исходная цель, opt-in и разрешение. Автоматической подстановки новой цели нет.

`Change` возвращает состояние, согласованные `data/asOf`, затронутые ID и возможность Undo. `change.report(...)`/`change.day(...)` используют тот же снимок. ID удалённой сессии может оставаться в списке затронутых, хотя её уже нет в новых данных. Undo относится к последней доступной правке и точной ревизии, хранится в памяти `Tracker` и не обещается после перезапуска.

## Запуск и выбор

`start(token, selection?, note?)` начинает новую сессию; активная сессия блокирует второй запуск. Pause закрывает рабочий сегмент, Resume открывает следующий в той же сессии, Stop завершает сессию. Switch атомарно завершает текущую сессию и начинает другую, включая переход из паузы.

`tracker.selection(cardId)` возвращает актуальные defaults доступной карточки. `tracker.typeSelection(typeId)` требует существующий, неархивный тип с `selectable=true`. Узел с `selectable=false` — группа для навигации; создать через него запускаемую карточку тоже нельзя. Флаги родителя не наследуются автоматически: доступный выбираемый потомок остаётся доступным.

```kotlin
val choices = tracker.view().choices()
val page = choices.search(ChoiceQuery(text = query))
// В обработчике нажатия Start для выбранного результата:
val hit = page.items.getOrNull(selectedIndex) ?: return
if (hit.entry.canStart) {
    tracker.start(page.token, hit.entry.selection, hit.entry.note)
}
```

`hit.entry.canStart` описывает пригодность классификации. Состояние таймера, Focus и актуальность token всё равно проверяет команда. GROUP и архивные результаты можно показать для просмотра/настройки. Подробности paging, cursor и suggestions — [CHOICES](CHOICES.md).

Repeat создаёт новую сессию с параметрами последнего сегмента и заметкой выбранной сессии. Favorite хранит snapshot классификации. Количества и длительность не копируются. Явные Repeat/Favorite допускают сохранённый исторический архивный вариант; автоматические предложения его исключают. Для новой сессии фиксируется текущий путь типа, прошлые сегменты сохраняют `ancestorPathAtWrite`.

Сохранение/копирование карточки или Favorite не меняет активную сессию и историю. Карточка может иметь `activityTypeId=null`. Имена, aliases и похожесть текста не выполняют автоматическую классификацию.

## Изменение истории и классификации

| API | Назначение |
|---|---|
| `labelCurrent` | Явно назначить классификацию текущей сессии без изменения её времени. |
| `changeDetails` | Изменить параметры с текущего момента; при работе разделить сегмент, при паузе изменить следующий выбор. |
| `manual` | Записать явно подтверждённый положительный интервал; конец не в будущем, пересечения запрещены. |
| `correctSegment` | Изменить закрытый сегмент, сохранив его ID и ссылки измерений. |
| `correctSession` | Атомарно сохранить все существующие сегменты завершённой сессии и заметку; каждый ID передаётся один раз. |
| `previewCorrection` / `applyCorrection` | Показать старые/новые суммы на одном asOf до применения. |
| `previewBoundary` / `correctBoundary` | Передвинуть общую границу двух закрытых сегментов разных завершённых сессий атомарно. |
| `switchedEarlier` | Разделить текущий непрерывный сегмент по явной прошлой границе; через паузы граница не переносится. |
| `resolveTail` | Подтвердить неизвестный хвост интервалом либо исключить его через `(null, null)`. |

При правке времени/заметки с прежним типом старый исторический путь сохраняется. Для пересчёта по текущему дереву требуется `reclassify=true`. Измерения не делятся пропорционально времени; исправление границы не меняет их target IDs. Отмена формы до Apply ничего не записывает.

Новый смысл ActivityType требует нового ID: `saveType` не меняет `meaningVersion/definition` существующего ID. Переименование, parentId, aliases, selectable, архив и подсказки редактируемы. `saveAxis/saveMetric/saveUnit/addCatalog` используют ту же транзакционную границу. После импорта проверять `change.catalogImport.entries`: конфликтующий объект сохраняется локально; остальные корректные новые определения могут быть добавлены. Дубликаты ключей и невалидные ссылки отклоняют команду. Модель — [CATALOG_IMPACT](CATALOG_IMPACT.md).

## Время и отчёты

Обычный таймер использует wall start и boot/elapsed anchor. Сон входит в `elapsedRealtime`. Монотонная длительность авторитетна в пределах загрузки. Другая загрузка, потеря опоры или расхождение wall/elapsed больше 1000 ms требует RECOVERY. Этот допуск относится к сравнению часов; длительности не округляются. Скачок wall clock, полностью отменённый между наблюдениями, нельзя обнаружить без наблюдений.

`Reports.report` применяет `[start,end)`, один now и dedup по segment ID. Соседние окна используют одинаковое целочисленное распределение миллисекунд. `unresolved` содержит подходящие неопределённые сегменты; их принадлежность конкретному окну не доказана. Пользователь решает хвост явно.

`day/calendar` строят границы через `ZoneId/LocalDate`. DST-дни 23/25 часов поддерживаются; целиком пропущенная местная дата и страница через неё возвращают `INVALID_INTERVAL`. `compare` сравнивает равные физические интервалы, `compareCalendarDays` — одинаковое число местных дней. Неполные окна помечаются, данные не экстраполируются; при нулевой базе percent=null.

`byType/byFacet` могут пересекаться: их суммы нельзя складывать в общий итог. Измерения в Report относятся к полным затронутым SESSION/SEGMENT; UI показывает эту область. `quantityTotals()` объединяет только SUM/legacy-поля по `(fieldId, meaningVersion, unit, scope)` и каждому ID один раз. BY_TARGET возвращается отдельно. Ноль отличается от отсутствия записи. CSV `SPREADSHEET_SAFE` экранирует формулы, `EXACT` сохраняет текст; переносимый CSV HistoryTransfer также точный.

Для ввода числа использовать `data.prepareMeasurement(MeasurementDraft(...))`. Сохранять исходный draft в форме. При `measurement=null` показать ошибку и предложить исправление/отмену; автоматического округления нет. Зарегистрированная метрика сохраняет каноническую единицу. Подробности — [CATALOG_IMPACT](CATALOG_IMPACT.md).

## Backup и файловый ввод

`backups.export()` захватывает Dataset/Moment в короткой транзакции; сериализация и запись SAF происходят после неё. Корень JSON: `formatVersion=7`, `backupId`, `asOf`, `data`. Данные включают словари, карточки, Favorite, сессии, сегменты, измерения, настройки, Goals и Focus. Reader мигрирует версии 1–6 в текущую модель. Исследовательские исходники переносятся отдельно.

Ограниченный CSV-вход использует HistoryFiles.inspect: 10 MiB, строгий UTF-8 и BOM. Полный SAF restore использует потоковый Backups.prepare над private staged файлом без общего 10 MiB cap. Табличный текст требует явного сопоставления колонок, времени, зоны, единиц и классификации. [FILE_IMPORT](FILE_IMPORT.md) описывает полный путь.

`prepare` только проверяет и создаёт preview. UI показывает состав, `unfinishedTail/unfinishedFocus` и последствие полной замены. Только подтверждение вызывает `apply`. Ядро сохраняет текущую копию, читает/проверяет её, повторно проверяет token и заменяет Dataset атомарно. Ошибка или stale preview сохраняет исходные данные. Rollback находится в приватном `noBackupFilesDir/rollback`; автоматического удаления нет.

Перенос не сохраняет device anchors. Открытый хвост остаётся незавершённым и требует RECOVERY; `asOf` не превращается в конец. Активная фаза Focus также требует recovery, paused Focus можно продолжить явно. Restore не делает merge и может удалить записи, созданные после снимка; повторное применение требует нового preview.

## Focus, Goals и локальные входы

[FOCUS](FOCUS.md), [GOALS](GOALS.md) и [LOCAL_ENTRIES](LOCAL_ENTRIES.md) задают специализированные операции поверх того же Tracker. Focus использует одну историю рабочих сегментов; перерывы не начисляют рабочее время и следующая фаза запускается явно. Goals рассчитывают прогресс из истории без фонового цикла. EntryDraft — временная форма, до Start-now или manual-save база не меняется.

Общий `settings` изменяет Focus defaults будущих запусков. `configureFocus` также меняет план будущих фаз активного запуска, сохраняя бюджет текущей фазы. UI не должен смешивать эти операции.

## Android-поверхности и ошибки

Widget/notification/overlay/launcher передают исходный token в общий runtime. Preference и OS permission различаются. Отказ разрешения не блокирует локальный таймер. Названия и заметки не попадают в безопасный текст lock screen. Overlay имеет собственный обязательный FGS-индикатор; обычный таймер сервиса не требует. Подробности — [ANDROID adapters](BACKEND_V13.md).

Основные ошибки: `STALE`, `INVALID_INTERVAL`, `OVERLAP`, `INVALID_INPUT`, `STORAGE`, `UNSUPPORTED_IMPORT`, `RECOVERY_REQUIRED`. Не озвучивать каждую секунду; озвучивать переход состояния. Техническая оболочка и Robolectric-проверки не заменяют проверку физического устройства.

Готовый каталог обновляется через [проверяемые обобщённые правила](RUNTIME_CATALOG.md). Старые локальные названия/архивность/aliases и история сохраняются; произвольный смысловой конфликт отклоняется.

## Устойчивые формы и восстановление

Подтверждённые correction и CSV previews содержат защищённые копии вложенной классификации, provenance и error/warning lists. Изменение исходной формы после preview не меняет Apply. Карточка выбирается по ID. Последний Repeat/correction выбирается по recorded end/start/id; добавленный позже старый интервал не становится последним.

SAF export передаёт только operation ID через Bundle; форма хранится private file. Recovery UI доступен до открытия runtime. [PORTABILITY](PORTABILITY.md) описывает journal, archive и ограничения.

Новая установка сохраняет локальную зону устройства один раз. Изменение reportZone требует явного подтверждения и не меняет физические интервалы или зоны Goals. Focus и Calendar требуют opt-in; all-day не создаёт рабочий интервал.

## Независимость команд от формы выбора

Start, Switch, разметка, ручная запись и Start Focus используют выбранную карточку и её уточнения. Missing/archived ID отклоняется; форма сохраняется для исправления. Undo, Repeat, resolveTail и переходы/завершение существующего Focus не читают выбранную карточку. Устаревший ID после restore или архивирования не блокирует эти действия и не подмешивает уточнения формы в сохранённый вариант. Таймерные Pause/Resume/Stop также независимы от выбранной карточки.
