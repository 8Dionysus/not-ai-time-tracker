# Контракт интеграции UI · v1

## Вход и исполнение

Получить `TrackerRuntime.get(applicationContext)` на `Dispatchers.IO`. Все команды, backup и чтения хранилища блокирующие, вызывать на IO. `tracker.snapshots` — Flow состояний после сохранений. Для анимации UI может раз в секунду запросить `snapshot()`; это чтение, не запись, и не требует сервиса. При возвращении приложения запросить актуальный снимок. Системная загрузка определяется `Settings.Global.BOOT_COUNT`; нельзя заменять её случайным ID процесса.

Каждая команда принимает **Token(datasetId, revision, sessionId)** из показанного пользователю состояния. Не подменять его свежим токеном непосредственно перед исполнением старого нажатия. Команды проверяют токен внутри одной транзакции. Проверка ревизии внутри транзакции даёт `CoreError(STALE)` с `currentState`, а не повторно применяет действие к другой сессии. Исключение текущей реализации: ранний отказ `undo` (нет доступной отмены или неверный её токен) возвращает STALE без currentState; UI должен запросить snapshot(). Глобальная ревизия консервативна: изменение настройки тоже делает старую форму устаревшей.

`Change` возвращает новое состояние, ID затронутых сессий и доступность Undo. Суммы получают через `Reports`, используя возвращённое/прочитанное согласованное состояние и одно значение Clock.now. Встроенного журнала команд нет. Отмена хранится только в памяти текущего `Tracker`, действует для последней доступной правки и точной ревизии. Любая следующая команда либо импорт делает старую отмену недоступной; после перезапуска она не обещается.

## Операции

| Операция | Семантика |
|---|---|
| `start(token, selection?, note?)` | Новая сессия, можно без карточки. При текущей сессии отклоняется. |
| `pause`, `resume`, `stop` | Пауза закрывает отрезок; resume открывает следующий в той же сессии; stop завершает сессию. |
| `switch(token, selection)` | Атомарно закрывает текущую сессию и начинает новую; работает и из паузы. |
| `labelCurrent` | Явно назначает классификацию всем отрезкам текущей сессии, сохраняя времена. Для поздней разметки. |
| `changeDetails` | Меняет параметры текущей карточки с этого момента: при учёте разделяет сегмент; на паузе меняет выбор следующего. Другую карточку задаёт switch. |
| `repeat` | Новая сессия с параметрами последнего сегмента и заметкой выбранной сессии; количественные достижения не копируются. |
| `saveFavorite`, `startFavorite` | Сохранённый снимок параметров, одинаковый путь запуска. |
| `saveCard`, `copyCard` | Создание/переименование/настройки/архив через данные. Копия с новым ID, без истории и количеств. |
| `Catalog.card(templateId)` | Создать личную карточку из шаблона; затем saveCard. Каталог не переписывает личные карточки. |
| `measure` | Одно самостоятельное значение поля, версии смысла, единицы и scope. Отсутствие записи ≠ ноль. |
| `manual` | Только Save: явные start/end, конец не в будущем. Нет записи на стадии заполнения формы. |
| `correctSegment` | Правка закрытого отрезка: границы и классификация. Ссылки измерений на его ID сохраняются. |
| `switchedEarlier` | Время внутри текущего непрерывного сегмента; атомарно сохраняет A до границы и B после неё. Не переносится через паузы по догадке. |
| `resolveTail` | Явные границы для неопределённого открытого хвоста либо `(null,null)` для его исключения. После решения сессия завершена. |
| `undo`, `settings` | Ревизионная одношаговая отмена; настройка явной зоны отчётов. |

Сохранение избранного/карточки не меняет историю и активный выбор. Repeat и Favorite используют сохранённую классификацию, даже если карточку позже переименовали/архивировали. Для нового обычного запуска `selection(cardId)` возвращает актуальные умолчания неархивной карточки. `Classification.partOf` — явно выбранный смысловой ключ широкой области (`language`, `fitness` и т.п.); совпадение имени не создаёт связь. Уточнения и tags — данные, пользовательские значения проходят тот же путь.

## Состояния и ошибки

`IDLE`, `RUNNING`, `PAUSED`, `RECOVERY`. Снимок включает Token, сессию, активный отрезок, достоверную длительность в целых ms, флаг сомнительных календарных отметок, безопасную подпись и доступные действия. Ошибки: `STALE`, `INVALID_INTERVAL`, `OVERLAP`, `INVALID_INPUT`, `STORAGE`, `UNSUPPORTED_IMPORT`, `RECOVERY_REQUIRED`. Текст ошибки не содержит заметок и имён занятий.

Не озвучивать каждую секунду; озвучивать переход состояния. Не использовать `session.selection.name` и note на заблокированном экране по умолчанию. Снимки не требуют разрешений Android.

## Время, история, отчёты

Текущий отрезок хранит wall start и boot/elapsed anchor. Сон входит в elapsedRealtime. Монотонная длительность авторитетна в пределах загрузки. Сдвиг wall относительно elapsed больше 1000 ms или другая загрузка вызывает RECOVERY. Это явная техническая погрешность сравнения двух часов, не округление длительности. При перезагрузке неизвестный хвост не получает догаданной длительности; ранее закрытые отрезки остаются точными. Без постоянного сервиса нельзя обнаружить скачок часов, который произошёл и полностью отменился между наблюдениями.

`Reports.report(data, now, start, end, filter)` применяет `[start,end)`, использует один now, dedup по segment ID и целые ms. Для малой рассинхронизации wall/elapsed в пределах допуска пропорциональные границы считаются целочисленно с одинаковой функцией конца; соседние окна не теряют миллисекунды. Большая неопределённость не распределяется. `unresolved` — список для отдельного предупреждения; принадлежность этих данных окну не утверждается.

`day` строит границы календарём указанной зоны. `byCard`, `byDetail` дают распределения, пустой ключ означает неуточнённое. Пересекающиеся tag/partOf фильтры — самостоятельные срезы, их нельзя складывать. `recordedDays` отражает возвращения, `calendarDays` — другой знаменатель; `hasRecords=false` не утверждает отсутствие реальной активности. `compare` принимает одинаковый фильтр, требует равную физическую длину окон и отмечает неполное окно; при нулевой базе percent=null, абсолютная разница остаётся.

Измерения в Report относятся к полным затронутым target, **не являются количествами внутри окна**. UI должен показывать подпись «за всю сессию/сегмент». Они не распределяются по дням/долям. CSV пишет их отдельными строками по одному разу. Не складывать их из разных дневных отчётов. CSV режим по умолчанию `SPREADSHEET_SAFE` экранирует потенциальные формулы; `EXACT` сохраняет текст. JSON точный и не получает CSV-префиксов.

## JSON и восстановление

`backups.export()` получает согласованный снимок и возвращает строку. Запись через SAF производится после выхода из транзакции. Корневые поля: formatVersion=1, backupId, asOf, data; data содержит datasetId/revision, cards/favorites/sessions/segments/measurements/settings. Схема Room отдельно имеет version=1; миграций пока нет и destructive fallback не включён.

`prepare(json)` полностью парсит/проверяет формат, ID, ссылки, состояние и интервалы. Возвращает неприменённый RestorePreview со счётчиками, asOf, unfinishedTail и текстом последствий. UI показывает состав и полную замену; отмена ничего не меняет.

Только явное подтверждение вызывает `apply(preview)`. Ядро сохраняет текущий JSON в RollbackStore, читает назад и проверяет его, затем проверяет неизменность локальной ревизии и атомарно заменяет данные вместе с настройками. Room сверяет прочитанные после записи данные внутри транзакции; ошибка откатывает всё. Файлы rollback находятся в `noBackupFilesDir/rollback`, сохраняются уникально и доступны через возврат `rollbackReference`/PrivateRollbackStore.read. Автоматического удаления копий нет. Повторный импорт требует нового preview и снова может удалить новые локальные данные.

Открытый хвост сохраняет известную длительность до asOf, но end остаётся null. Импорт убирает boot anchor, переводит хвост в RECOVERY; `asOf` не становится окончанием автоматически. Пользователь подтверждает/исправляет интервал или исключает хвост. Пауза импортируется как пауза без активного хвоста. Восстановление не запускает время в прошлом.

## Ограничения оболочки

Технические поля требуют ISO-8601, имя существующей карточки выбирается точно. Это отладочный интерфейс, не утверждённый UX. Работа с SAF после уничтожения Activity может потребовать повторного экспорта; ядро при этом сохраняет историю. Нет заявленной проверки на реальном телефоне без отдельного доказательства в VERIFICATION.md.
