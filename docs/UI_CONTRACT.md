# Контракт интеграции UI · v2

## Вход и исполнение

Получить `TrackerRuntime.get(applicationContext)` на `Dispatchers.IO`. Все команды, backup и чтения хранилища блокирующие, вызывать на IO. `tracker.snapshots` — Flow состояний после сохранений. Для анимации UI может раз в секунду запросить `snapshot()`; это чтение, не запись, и не требует сервиса. При возвращении приложения запросить актуальный снимок. Системная загрузка определяется `Settings.Global.BOOT_COUNT`; нельзя заменять её случайным ID процесса.

Каждая команда принимает **Token(datasetId, revision, sessionId)** из показанного пользователю состояния. Не подменять его свежим токеном непосредственно перед исполнением старого нажатия. Команды проверяют токен внутри одной транзакции. Проверка ревизии даёт `CoreError(STALE)` с `currentState`, включая ранний отказ Undo, а не повторно применяет действие к другой сессии. Глобальная ревизия консервативна: изменение настройки тоже делает старую форму устаревшей.

`Change` возвращает новое состояние, ID затронутых сессий, `changedSessions`, `changedSegments`, доступность Undo, согласованные `data` и `asOf`. `change.report(...)`/`change.day(...)` пересчитывают суммы из этого снимка с тем же now, даже если после команды появились новые изменения. Изменение/удаление Measurement также включает связанную сессию в changedSessionIds. Если сессия удалена при исключении хвоста, её ID присутствует в списке затронутых, но в данных после правки её нет. Встроенного журнала команд нет. Отмена хранится только в памяти текущего `Tracker`, действует для последней доступной правки и точной ревизии. Любая следующая команда либо импорт делает старую отмену недоступной; после перезапуска она не обещается.

## Операции

| Операция | Семантика |
|---|---|
| `start(token, selection?, note?)` | Новая сессия, можно без карточки. При текущей сессии отклоняется. |
| `pause`, `resume`, `stop` | Пауза закрывает отрезок; resume открывает следующий в той же сессии; stop завершает сессию. |
| `switch(token, selection)` | Атомарно закрывает текущую сессию и начинает новую; работает и из паузы. |
| `labelCurrent` | Явно назначает классификацию всем отрезкам текущей сессии, сохраняя времена. Для поздней разметки. |
| `changeDetails` | Меняет параметры текущей карточки с этого момента: при учёте разделяет сегмент; на паузе меняет выбор следующего. Другую карточку задаёт switch. |
| `repeat` | Новая сессия с параметрами последнего сегмента и заметкой выбранной сессии; количественные достижения не копируются. |
| `saveFavorite`, `startFavorite`, `removeFavorite` | Сохранённый снимок параметров, одинаковый путь запуска; явное снятие избранного. |
| `saveCard`, `copyCard` | Создание/переименование/настройки/архив через данные. Копия с новым ID, без истории и количеств. |
| `Dataset.cardFromType(typeId)` | Создать личную карточку из шаблона; затем saveCard. Каталог не переписывает личные карточки. |
| `measure`, `removeMeasurement` | Одно самостоятельное значение поля, версии смысла, единицы и scope; удаление ошибочного значения. Отсутствие записи ≠ ноль. |
| `saveType` | Создание, переименование или архивирование типа с сохранением его ID. |
| `manual` | Только Save: явные start/end, конец не в будущем. Нет записи на стадии заполнения формы. |
| `correctSegment` | Правка закрытого отрезка: границы и классификация. Ссылки измерений на его ID сохраняются. |
| `correctSession` | Атомарное сохранение всех существующих сегментов завершённой сессии и заметки. Передать каждый ID один раз; измерения сохраняют ссылки. |
| `switchedEarlier` | Время внутри текущего непрерывного сегмента; атомарно сохраняет A до границы и B после неё. Не переносится через паузы по догадке. |
| `resolveTail` | Явные границы для неопределённого открытого хвоста либо `(null,null)` для его исключения. После решения сессия завершена. |
| `undo`, `settings` | Ревизионная одношаговая отмена; настройка явной зоны отчётов. |

Сохранение избранного/карточки не меняет историю и активный выбор. Repeat/Favorite сохраняют выбранный тип и уточнения, даже после переименования/архива карточки; для новой сессии фиксируют текущий путь этого типа. selection(cardId) возвращает актуальные умолчания доступной карточки. Одно дерево ActivityType служит выбору и roll-up. activityTypeId — единственная связь, ancestorPathAtWrite — исторический путь; null допускается. Смена связи карточки действует на будущие запуски. Переименование, aliases и похожесть текста не классифицируют историю. Пять узлов bootstrap — технические данные совместимости, не полный каталог.

## Состояния и ошибки

`IDLE`, `RUNNING`, `PAUSED`, `RECOVERY`. Снимок включает Token, сессию, активный отрезок, достоверную длительность в целых ms, флаг сомнительных календарных отметок, безопасную подпись и доступные действия. Ошибки: `STALE`, `INVALID_INTERVAL`, `OVERLAP`, `INVALID_INPUT`, `STORAGE`, `UNSUPPORTED_IMPORT`, `RECOVERY_REQUIRED`. Текст ошибки не содержит заметок и имён занятий.

Не озвучивать каждую секунду; озвучивать переход состояния. Не использовать `session.selection.name` и note на заблокированном экране по умолчанию. Снимки не требуют разрешений Android.

## Время, история, отчёты

Текущий отрезок хранит wall start и boot/elapsed anchor. Сон входит в elapsedRealtime. Монотонная длительность авторитетна в пределах загрузки. Сдвиг wall относительно elapsed больше 1000 ms или другая загрузка вызывает RECOVERY. Это явная техническая погрешность сравнения двух часов, не округление длительности. При перезагрузке неизвестный хвост не получает догаданной длительности; ранее закрытые отрезки остаются точными. Без постоянного сервиса нельзя обнаружить скачок часов, который произошёл и полностью отменился между наблюдениями.

`Reports.report(data, now, start, end, filter)` применяет `[start,end)`, использует один now, dedup по segment ID и целые ms. Для малой рассинхронизации wall/elapsed в пределах допуска пропорциональные границы считаются целочисленно с одинаковой функцией конца; соседние окна не теряют миллисекунды. Большая неопределённость не распределяется. `unresolved` — список для отдельного предупреждения; принадлежность этих данных окну не утверждается.

`day` строит границы календарём указанной зоны. `byCard`, `byDetail` дают распределения, пустой ключ означает неуточнённое. Пересекающиеся tag/activityTypeId фильтры — самостоятельные срезы, их нельзя складывать. `recordedDays` отражает возвращения, `calendarDays` — другой знаменатель; `hasRecords=false` не утверждает отсутствие реальной активности. `compare` сравнивает равные физические интервалы. `compareCalendarDays` принимает даты начала и одинаковое число календарных дней, одну зону и фильтр; 23/25-часовые DST-дни поддерживаются. Оба варианта отмечают неполное окно, не экстраполируют и не масштабируют значения; при нулевой базе percent=null, абсолютная разница остаётся.

Измерения в Report относятся к полным затронутым target, **не являются количествами внутри окна**. UI должен показывать подпись «за всю сессию/сегмент». `quantityTotals()` считает каждый ID один раз и возвращает отдельные суммы по `(fieldId, meaningVersion, unit, scope)`. Разные версии, единицы, scope и поля не складываются. Ноль возвращается как 0, отсутствующее поле отсутствует в карте. Величины суммируются точно через Decimal без границы Long; временные суммы проверяют Long и дают INVALID_INTERVAL при переполнении. Они не распределяются по дням/долям. CSV пишет их отдельными строками по одному разу. Не складывать их из разных дневных отчётов. CSV режим по умолчанию `SPREADSHEET_SAFE` экранирует потенциальные формулы; `EXACT` сохраняет текст. JSON точный и не получает CSV-префиксов.

## JSON и восстановление

`backups.export()` получает согласованный снимок и возвращает строку. Запись через SAF производится после выхода из транзакции. Корневые поля: formatVersion=2, backupId, asOf, data; data содержит datasetId/revision, types/cards/favorites/sessions/segments/measurements/settings. Схема Room отдельно имеет version=1; миграций пока нет и destructive fallback не включён.

`prepare(json)` полностью парсит/проверяет формат, ID, ссылки, состояние и интервалы. Возвращает неприменённый RestorePreview со счётчиками, asOf, unfinishedTail и текстом последствий. UI показывает состав и полную замену; отмена ничего не меняет.

Только явное подтверждение вызывает `apply(preview)`. Ядро сохраняет текущий JSON в RollbackStore, читает назад и проверяет его, затем проверяет неизменность локальной ревизии и атомарно заменяет данные вместе с настройками. Room сверяет прочитанные после записи данные внутри транзакции; ошибка откатывает всё. Файлы rollback находятся в `noBackupFilesDir/rollback`, сохраняются уникально и доступны через возврат `rollbackReference`/PrivateRollbackStore.read. Автоматического удаления копий нет. Повторный импорт требует нового preview и снова может удалить новые локальные данные.

Открытый хвост сохраняет известную длительность до asOf, но end остаётся null. Импорт убирает boot anchor, переводит хвост в RECOVERY; `asOf` не становится окончанием автоматически. Пользователь подтверждает/исправляет интервал или исключает хвост. Пауза импортируется как пауза без активного хвоста. Восстановление не запускает время в прошлом.

## Ограничения оболочки

Технические поля требуют ISO-8601, имя существующей карточки выбирается точно. Это отладочный интерфейс, не утверждённый UX. Работа с SAF после уничтожения Activity может потребовать повторного экспорта; ядро при этом сохраняет историю. Нет заявленной проверки на реальном телефоне без отдельного доказательства в VERIFICATION.md.


## Дополнение v2: дерево, оси, точные измерения

Полный актуальный контракт — CATALOG_IMPACT.md. В старых вызовах заменить partOf на activityTypeId. Не задавать ancestorPathAtWrite вручную: start/switch/manual/label/correct вычисляют его внутри транзакции; отчёт использует сохранённый путь. typeSelection(typeId) допускает широкую группу без предварительного создания карточки. Dataset.cardFromType создаёт личную копию любого доступного узла. Null type допустим.

saveAxis/saveMetric/saveUnit/addCatalog работают через тот же Token. Новые dictionaries входят в JSON/Room. Measurement принимает value=Decimal("2.5") или прежний Long через конструктор совместимости; copy(value=...) теперь принимает Decimal. quantityTotals возвращает Map<QuantityKey,Decimal>, агрегирует только SUM или legacy поля. BY_TARGET доступен отдельными значениями в Report.measurements. В CSV значение — точная строка; добавлены activity_type_id, ancestor_path и facets. JSON v2 не заменяет JSON v1 без миграции; Backups.decode/prepare поддерживают оба.

Пример: Facet("axis.language", valueId="es", valueMeaningVersion=1); свободная ось: Facet("axis.source", text="YouTube"). Определения предварительно устанавливаются через addCatalog/saveAxis; примеры ID иллюстрируют API и не заявляют наличие полного каталога. Filter(facets=listOf(a,b), facetMatch=FacetMatch.ANY) — объединение по сегментам; ALL — пересечение. Остальные условия фильтра сохраняют AND.

При правке заметки/времени с прежним activityTypeId сохраняется прежний исторический путь. Для явного пересчёта по текущему дереву передать reclassify=true. UI сначала вызывает previewCorrection(sessionId, edits, note, reclassify): он не пишет в базу и через preview.reports возвращает старые/новые суммы на одном asOf. После подтверждения — applyCorrection(preview), с сохранённым Token и одношаговой Undo. Отмена формы не требует команды. Прямая correctSession остаётся командой Save; массовой переклассификации нескольких сессий нет.


### Уточнение API после предметной приёмки

Для нового смысла ActivityType создайте новый ID: saveType не разрешает изменять meaningVersion/definition прежнего ID. Переименование/перенос/архив остаются разрешены. Архив/невыбираемость родителя не каскадируют на потомков. Обычный start/switch проверяет выбранный тип даже для прямой Classification; явный Repeat/Favorite разрешает исторический выбор.

После addCatalog проверяйте change.catalogImport!!.entries (ADDED/UNCHANGED/CONFLICT); успех команды не означает применение конфликтующих определений. Повторный ключ во входе — INVALID_INPUT без изменения базы. Неизвестные suggestedAxisIds/suggestedMetricIds также отклоняются.

Для ввода количества используйте data.prepareMeasurement(MeasurementDraft(metricId, meaningVersion, value, unitId, scope, targetId)). Сохраняйте returned draft в форме. Если measurement=null, покажите error и оставьте ввод для явного исправления/отмены. При наличии measurement вызовите tracker.measure с токеном показанного состояния. Метод не округляет и не сохраняет черновик в базу; оригинальная единица не подменяет каноническую при неудаче преобразования.

Экспорт JSON теперь проверяется на пригодность для собственного восстановления до возврата строки: общий лимит 10 MiB в UTF-8, допустимые часы, ссылки и временные основания. Ошибка не меняет базу и не означает наличие готовой копии. Если календарные часы переведены раньше уже записанных определённых интервалов, требуется разобраться с часами/временем перед успешным экспортом; timestamps молча не меняются. Полный restore остаётся заменой: повторное применение может удалить новые локальные записи, rollback-файл позволяет явно восстановить состояние перед заменой.


### Адаптер корпуса 0.5

ResearchCatalog.read проверяет полный источник и возвращает план без записи. plan.apply требует явных selectedIds/selectedAxisIds, текущего Token и ResearchArchive; результат Change.catalogImport по-прежнему показывает ADDED/UNCHANGED/CONFLICT. Новые researchOrigins в типах/осях сохраняют source-qualified provenance. JSON formatVersion=3 читает прежние 1/2; Room 2 совместим с прежними payload без origins. Исходный исследовательский файл хранится отдельно по SHA-256, не включается в обычную JSON-копию. Не считать успешный импорт выбранной проекции завершением всех исследовательских слоёв. Полный контракт — RESEARCH_ADAPTER.md.


Полный корпус каталога 0.7 устанавливается через FullResearchCatalog / FullResearchPlan.apply; см. [FULL_CATALOG_07.md](FULL_CATALOG_07.md). UI использует тот же Tracker и не пересчитывает whole/component время самостоятельно.
